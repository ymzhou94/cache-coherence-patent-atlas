TLBI 流量怎样拖延另一个 CPU 核心的 DSB

同一个目标核心要服务来自 guest 的 TLBI 与 host 的 DSB。后者等到目标端完成其相关工作后才收到响应。

  1. guest 发出的翻译维护 原图 3 的 guest 核心向其他核心发送连续 TLBI。
  2. host 发出的独立屏障 host 核心需要目标核心处理 DSB。延误可能传递到这个核心。
  3. 关联事件触发维护 满足延期条件时，目标核心先保存标记。关联事件到达后才使标记的条目失效。
