发起方把复用判断编码到请求，系统缓存决定是否采用

group ID 标记数据流，cache hint 指定这笔请求的分配或释放意图。控制器仍要读标签和配置才能决定是否分配、维持或改变行状态。

  1. 发起方生成 cache hint 已预期会复用的数据可申请 sticky；只读一次或随后接管数据可考虑不分配或解除分配。发起方可以是内核组件、计算引擎或上游缓存。
  2. 控制器根据组配置解释请求 部分实施例按 group ID 启用 hint。No Hint 的例子读取全局缺省分配策略。
  3. 标签中的状态和 group ID 各司其职 地址走标签比较，状态决定 sticky 等保护，group ID 保留数据流归属。实际分配和逐出仍由系统缓存控制器完成。
