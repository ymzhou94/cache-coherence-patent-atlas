地址早送给预取器，指令本体送往协处理器缓冲

CPU 的 store queue 同时供监视与正式交付。预取电路收到转换地址即可申请缓存数据，指令随后走独立交付路径。

  1. CPU store queue 本图专用原图 2 的 store queue 监视方式。协处理器指令被缓冲于此，普通 CPU store 也可使用这个队列。
  2. 协处理器指令缓冲 一条待执行协处理器指令会经核心接口转入协处理器指令缓冲。其触发早晚和地址查询不同。
  3. 协处理器预取器 预取器读到协处理器指令相关信息后，向 CPU 的 TLB 查询对应操作数，得到真实物理地址再生成预取。
  4. 附地址的预取提示 原图 2 中的提示方向是协处理器预取器到 CPU 预取单元，供后者避免重复。
  5. 共享 L2 缓存 本图采用原图 3 的共享 L2 组织。它是一个实施例，缓存级别与共享关系并不是独立项的统一限制。
