取指组复用组内目标，预测器保留给第二次转移

Using a next fetch predictor circuit with short branches and return fetch groups

当预测跳转的目标已经被包含在当前 fetch group 中时，怎样避免重复取指，并仍然为同组的后续跳转提供预测？

  • 核心结论
  • 组内目标确认后，同一 NFP 条目替换目标字段
  • 保留 call 后的返回段，无需从返回地址重新读 I-cache
  • 前跳保留首段与目标段，跳过两者之间的字节
  • 后跳复制循环体，需计入退出时的恢复代价
  • 权利要求与出处
  • 关联专利

核心结论

取指器确认首个预测 taken 转移的目标在同一组内后，在 NFP 条目加标记，并把其目标字段换成第二个控制转移的目标。对于短前跳、后跳和 call 后的返回段，取指器用不同的缓冲处理复用已取回指令。

组内目标确认后，同一 NFP 条目替换目标字段

原图 1–5 改变 CPU 取指器、指令缓存、取指缓冲与预测表之间的路径。原图 10 和正文明确包含手机 SoC 与电池供电设备的 CPU 实施例。

原图 5 展开两个时点。同一个 fetch address 第一次命中时，NFP 给出第一目标。取指器对照已返回的指令组，发现目标也在组内，再标记这一条件并用组内第二个控制转移的目标更新同一项。随后命中标记时，可以用已取得的组处理第一个转移，把这一项的下一目标输出给后续取指。独权 1、8、14 都包含第二目标替换条件。

保留 call 后的返回段，无需从返回地址重新读 I-cache

原图 2 把 call 前缀放进指令缓冲，把 call 后已取得的返程指令留在 RFS。RAS 独立保存 return address（说明书示例还存 RFS indicator）。前端仍按 call target 取子程序；短子程序遇到 return 时可将 RFS 中的数据接到缓冲。分支只命中地址栈而无数据时，仍使用正常取指。

前跳保留首段与目标段，跳过两者之间的字节

当目标位于前跳地址之后且在当前组内，前端将组头至前跳和目标起点之后的两段连续入缓冲。节省的是对已在响应中的目标段再次发起读请求及占用缓冲的无效槽位。若后段还有下一控制转移，相关目标可占用新 NFP 字段。

后跳复制循环体，需计入退出时的恢复代价

当回跳目标在当前组较早位置，缓冲首段含组前缀及第一次循环，第二段只含完整循环体，继续执行时无需再取其字节。某些实现等待连续 taken 次数超过阈值后启用，说明书中的理论访问降幅依赖预期循环迭代数以及退出时清除额外副本的代价。
