工程要点

地址学习表在数据缓存被判定存有本次 load 的陈旧数据时降低对应条目的置信度。

成立条件
采用预测地址前须达到门槛。预测地址即使正确，程序顺序更早的未提交 store 也可能持有本次 load 应读的新值。
验证方法
固定预测与实算地址一致，对照学习器处理和忽略陈旧数据回报。记录每次置信度更新以及后续 load 发起但不能使用的早查次数。

工作机制

同一条 load 若常访问相同地址，可以提前查数据缓存。较老的未提交 store 若持有更新值，这次 load 仍要从 store queue 读到它。

独立于数据缓存的学习表按 load 身份保存地址预测和置信度。只有置信度到门槛才采用预测地址。收到对应的缓存值已陈旧的指示时，电路降低该 load 的置信度。部分实施例还验证地址及 store-to-load 数据路径。

  1. 按 load 身份学习访问地址

    学习表保存预测地址和置信度。实施例可以识别常量地址或步长，用实际算出的地址更新条目。

  2. 达到门槛后采用预测

    置信度达标时，才为后续执行选用学到的地址。从属实现还可分配独立预测表，数据值仍由数据缓存或 store queue 提供。

  3. 分别验证地址和数据来源

    核对预测地址与实际算出的地址，再检查是否有较早的 store 要转发。如果必须转发，数据缓存的值对本次 load 就可能已经过时。

  4. 收到陈旧指示时降低置信度

    在相应实施方式中，可以取消缓存查询并改从 store queue 取值。若预测地址本身不符，则走另一条失配和恢复路径。

权项与实施例约束

权 3 把学习表选出的预测地址写入另一张预测表。权 6 从该预测表读到的地址若在存储队列命中，可取消缓存查询，同时下调原学习项的置信度。

收益与开销

地址不符和命中陈旧缓存数据都可以给学习表负反馈，原因却分别落在寻址和数据来源。若只数预测地址命中，无法看到已经发出又无法使用的缓存读。

边界场景

若生产者先写环形缓冲，再由同一消费者指令读取，地址模式始终规则，但写入与读取的相对时序改变后，从缓存供数和从存储队列转发的比例可能反转。

条件推演

初始条件
假定 PC=0x30 的 load 已跨过置信门槛，预测和实算都是 0x8000。D-cache 存 7，一条程序顺序更早、尚未提交的 store 在同址存了较新的 9。
处理结果
实算地址与预测一致。D-cache 里的 7 已过时，这次 load 需要 9。采用相应的从属实施方式时，处理器从 store queue 取值，并降低该 load 的预测置信度。
结果解读
PC 0x30、地址 0x8000、值 7 和 9 都是算例参数。权利要求给出降置信度的条件，下调幅度由实现决定。

关联专利

  • 预测存储队列命中以提前发射依赖访存

    预测地址即使正确，US11829763B2 仍会检查存储队列。命中队列时取消按预测地址发起的数据缓存查询，改从队列取数据，并下调学习置信度。US9710268B2 预测较老 load 会否命中存储队列，分别在该 load 发射后 N 拍或较短的 M 拍发射依赖访存。

  • 分级存储队列与地址解析

    US12775463B2 的主存储队列可为多笔 load 同时搜索，次队列按单笔搜索。原图 5A 还给出一次 load 的字节由不同队列或数据缓存提供时的合并例。US11829763B2 在预测地址命中存储队列时取消预测发起的数据缓存查询，改从队列取数。两件分别处理多来源装配和早查缓存何时让位给队列数据。

  • 抑制曾经无用的预取地址

    US11829763B2 在预测地址命中存储队列时降低这一 load 的地址预测置信度。US12306762B1 在预取行逐出且未被使用时，给相应地址累加计数。后续同址候选的计数达到阈值时，限制表拒绝该预取。一边反馈的是数据缓存能否提供该 load 的值，一边反馈的是预取驻留期间有没有被用到。
