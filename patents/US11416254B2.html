同一解码组内的零额外周期 load 旁路

Zero cycle load bypass in a decode group

同一解码组内，哪些条件允许 load 复用较早 store 的源物理寄存器？

工程要点

同组资格比较通过后，重命名器让 load 的目标架构寄存器引用 store 数据源的物理寄存器。

成立条件
store 在前、load 在后，且同一译码周期得到。其间的操作不得改写两者寻址所用的架构寄存器。
验证方法
固定 store 数据源就绪拍，对照普通 load 转发与组内映射复用。测消费者操作数就绪时间、分配的物理寄存器数和送入 LSU 的请求数。

工作机制

同组 store 与后续 load 即使需要传递同一份数据，常规取数也可能经过地址生成和 store queue。若解码阶段就能确认这种依赖，重命名即可把后续消费者接到现有的生产者。

硬件比较同一解码周期内的较早 store 和后续 load，同时检查其间是否有指令改写寻址寄存器。条件满足后，重命名器把 load 的目的寄存器映射到 store 数据源使用的物理寄存器。

  1. 在同一解码组找 store 与 load

    解码器同拍给出组内操作。比较电路找出较老的 store 和其后可能相关的 load，并以这组指令判断旁路资格。

  2. 检查中间指令是否改写寻址寄存器

    只要一条中间指令改写影响地址的架构寄存器，比较器就不能沿用旧 store 的等址判断。

  3. 复用 store 数据源的物理编号

    通过资格检查后，重命名器让 load 的目的映射使用 store 数据源的物理寄存器号。一种实现还可以跳过从 free list 取新编号。

  4. 消费者等源寄存器就绪

    之后读 load 目的值的指令都等这个源寄存器。省下的是普通 load 的数据路径，最早可消费时间仍由生产者何时写出该值决定。

权项与实施例约束

权 2 把相邻操作用于简化检查。权 3、4 还明确可比较同周期产生的操作码，以识别 store 之后具有地址依赖的 load。配对范围仍由译码组限定。

工程推演与验证

收益与开销

复用的是物理寄存器映射，最终省下的是消费者等待 load 数据返回的一段链路。原 store 的地址及提交责任仍在它自己的路径上，不能把少一次取数当作少一次写入。

边界场景

在同一缓存行上先写四字节、再读取覆盖八字节的 load 时，字节范围更宽。即使基址表达式相同，也不能只凭相等的寻址寄存器就让该 load 使用原 store 的单个值。

条件推演

初始条件
假定同一组依次解码 store [X1] ← X2、一条独立操作和 load X3 ← [X1]。两次访存均满足资格，中间操作不写 X1，X2 当前映射到 P17。
处理结果
重命名器可将 X3 也映射到 P17。后续读取 X3 的指令便从 P17 获得数据。若中间操作改写 X1，这个匹配分支便不能使用。
结果解读
这个序列采用相同的寻址形式，并假定其他资格满足。跨组、地址别名或操作宽度不同时，需要按各自条件判断。

专利原文

关联专利

  • 并行重放缓冲加快等待 store 数据的 load

    两件专利都处理 load 等待较早 store 数据的问题。同一解码组内能证明寻址寄存器未被中间指令改写时，前者把 load 目的重命名为 store 的源物理寄存器。后者在执行期才发现 store queue 地址命中、数据未到，用配对标识监听 store 数据操作的发射，再触发 load 重放。两者缩短的是不同阶段的等待，依赖值都仍需就绪。

  • 把依赖 load 的比较或运算移入 LSU

    US12547401B2 仍执行原始 load，把后续消费操作的比较或算术移到 LSU 处理。US11416254B2 则在同一解码组识别较早的 store，在地址及依赖条件满足时，把 load 目的映射到 store 数据源物理寄存器。两项机制作用在不同阶段，应分别量化比较结果可用延迟和被省去的数据通路。

  • 不同距离阵列组的可变且有界命中延迟

    US11893241B1 在缓存数据阵列回程仲裁处处理近远阵列同拍返回，近组可能多等一个周期。US11416254B2 在同一解码组中识别安全的 store 到 load 依赖，经寄存器重命名让该 load 使用已有物理寄存器。两项专利优化的是不同位置的加载依赖，适用条件分别是阵列回程争用和可证明的组内地址关系。
