按 store queue 命中预测加速指针追踪

Reducing latency for pointer chasing loads

追指针时，预测旧 load 的数据来源怎样改变后续访存的发射时间？

工作机制

指针链上，较老 load 读出的值要参与下一次访存的地址计算。如果数据缓存能把该值直接送进地址生成器，后续操作可能少等一段路径。若数据需要从 store queue 取得，短间隔就可能不够。

调度器预测较老的 load 是否会命中 store queue，再选择何时发射依赖结果的年轻访存。预测命中使用 N 周期，预测缺失使用较短的 M 周期。按说明书的实施例，数据缓存返回的指针可直接转发给年轻操作的地址生成单元。

  1. 找出下一次访存的生产者

    调度器识别年轻 load 或 store 对较老 load 结果的依赖。安排发射时可以先知道生产者身份，之后才收到具体的值。

  2. 预测较老 load 是否命中 store queue

    预测器可以用训练信息区分 store 转发和无法在短时间内供数的情况。预测 store queue 缺失后，数据缓存还须另行查询。

  3. 给两种预测设置不同间隔

    预测命中使用较长的 N，预测缺失使用较短的 M。若旧 load 的数据可直接从缓存旁路，返回拍可对齐年轻操作的地址生成阶段。

  4. 到地址生成时核对数据是否就绪

    地址计算使用实际读出的值。预测不准或数据缓存也缺失时，按实现推迟或重发。说明书还考虑了会增加流水阶段的对齐和符号扩展。

示例

初始条件
较老的指令从节点 p 读出 next，年轻指令访问 next+4。说明书举例比较普通约 4 拍与快速 3 拍或更少。这里取 4 和 3。
处理结果
旧 load 若在数据缓存命中，并把指针直接送到 LSU 的地址生成单元，年轻 load 可提前一拍发射。旧 load 若需要 store queue 数据，则按较长的 4 拍安排。
结果解读
独立权利要求只限定 M<N。这里的间隔取自说明书示例，两次访存各自还可能经历其他缓存阶段和等待。

收益与代价

何时有效
如果指针链规则、缓存命中稳定，每次地址生成少等一拍的效果可以在多个节点间累加。
代价和限制
频繁命中 store queue 或需要恢复时，早发的年轻访存可能重发，抵消一部分节拍收益。
验证指标
按缓存命中和缺失分组，记录旧 load 的数据来源、发射间隔、实际数据就绪时间与年轻访存重发率。

权利要求与出处

独立权利要求为第 1、8、14 项。下方列出部分权利要求的中文释义。

权 1
按较老 load 的 store queue 命中预测，以 N 拍或 M 拍间隔发射依赖访存。M 小于 N。
权 2
预测 store queue 缺失时，可把数据缓存的返回值转发给年轻访存的地址生成单元。

原文位置

独立权利要求 1
按较老 load 的 store queue 命中预测，选择 N 或 M 拍后发射年轻的依赖访存。M 小于 N。
说明书图 3–6、9

从属权利要求 2、4–6
这些项补充了向地址生成单元直接转发、预测对齐或符号扩展、形成地址，以及年轻操作可以是 store 的条件。
