预测存储队列命中以提前发射依赖访存

Reducing latency for pointer chasing loads

工程要点

发射逻辑依据较老 load 的存储队列命中预测，为依赖它的年轻访存安排较短或较长的发射间隔。

成立条件
短间隔适用于预测存储队列缺失。数据缓存返回可前递给地址生成器时，年轻访存才能按短间隔拿到正确地址输入。
验证方法
固定指针链和逐笔真实数据来源，对照一律用长间隔与按预测选间隔。记录相邻操作发射间隔、地址实际就绪时点及年轻操作重发次数。

工作机制

指针链上，较老 load 读出的值要参与下一次访存的地址计算。如果数据缓存能把该值直接送进地址生成器，后续操作可能少等一段路径。若数据需要从 store queue 取得，短间隔就可能不够。

核内指令发射逻辑根据较老 load 是否预计命中存储队列，决定何时发射其依赖访存。预计命中存储队列时等待 N 个周期，预计未命中时等待较短的 M 个周期。后一条路径可把 L1 数据缓存返回的指针直接转发给依赖操作的地址生成单元。

  1. 找出下一次访存的生产者

    核内指令发射逻辑识别年轻 load 或 store 对较老 load 的数据依赖，再根据预测的数据可用时间安排发射。

  2. 预测较老 load 是否命中 store queue

    预测器可以用训练信息区分 store 转发和无法在短时间内供数的情况。预测 store queue 缺失后，数据缓存还须另行查询。

  3. 给两种预测设置不同间隔

    预测命中使用较长的 N，预测缺失使用较短的 M。若旧 load 的数据可直接从缓存旁路，返回拍可对齐年轻操作的地址生成阶段。

  4. 到地址生成时核对数据是否就绪

    地址计算使用实际读出的值。预测不准或数据缓存也缺失时，按实现推迟或重发。说明书还考虑了会增加流水阶段的对齐和符号扩展。

权项与实施例约束

权 4 把对齐和符号扩展也放进预测条件。存储队列未命中预测只决定可尝试的调度时机，年轻地址生成实际还要接到满足格式要求的旧 load 结果。

工程推演与验证

收益与开销

缩短的是旧 load 到年轻访存发射之间的等待。若值还需要扩展或对齐调整，压力会转移到地址生成输入前的处理级，缓存数据阵列本身的读取时间可保持原样。

边界场景

同一链表循环可交替读自然对齐的整字指针与需扩展的压缩索引。后一类若使用相同的短间隔，即使都在数据缓存命中，也更容易赶不上年轻操作的地址生成拍。

条件推演

初始条件
较老的指令从节点 p 读出 next，年轻指令访问 next+4。说明书举例比较普通约 4 拍与快速 3 拍或更少。这里取 4 和 3。
处理结果
旧 load 若在数据缓存命中，并把指针直接送到 LSU 的地址生成单元，年轻 load 可提前一拍发射。旧 load 若需要 store queue 数据，则按较长的 4 拍安排。

关联专利

  • 把地址学习与陈旧缓存数据反馈结合

    地址学习方案即使算对地址，也要在发现 store queue 有更新数据时取消缓存查询并下调学习置信度。指针追踪方案预测的是旧 load 会不会命中 store queue，据此选择依赖它的年轻访存在第 M 拍还是第 N 拍发射。前者避免提前读到无用的旧值，后者用数据来源预测安排下一次地址生成。
