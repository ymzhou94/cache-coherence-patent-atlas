将缓存 way 暂时映射成独立的实时 RAM 地址区

Dynamic allocation of cache memory as RAM

同一缓存阵列中，怎样把一部分容量变为实时作业可直接寻址的 RAM，同时让其余部分继续缓存？转换和解除时的数据怎么办？

核心结论

控制器将选中的行设为实时内存并移出普通缓存操作，把它们映射到原本不活动的独立地址区。旧缓存脏数据可以先写回原地址。任务结束后可解除映射，直接 RAM 阶段的数据由使用方决定是否先复制。

转为直接 RAM 的 way B 与普通缓存共同留在阵列里

图 1 按原图 2 展开八组、四路。普通系统内存地址先算出 set，再查其 tag。way B 转换后，这条查找和回填路径只使用同一 set 内的 A、C、D。访问直接 RAM 区 B 时，地址定位的是转为 RAM 的 way B 对应位置。

授权第 1 项要求实时内存指示、与高于 bulk 的优先级关联，以及将选中缓存行排除出缓存操作。第 15 项改用处理器地址区和所选 way 表达，第 16 项规定指示可以位于选中缓存行的 cache tag。依第 20 项，还可只转换一个 way 的一半。

按图中结构枚举，普通缓存候选从 32 行变为 24 行，每个 set 的有效候选从 4 路变为 3 路。解除映射后恢复到 32 行。这个模型只验证阵列容量变化，其他代理的 miss 和尾延迟还取决于地址映射和工作集。

转换前处理旧脏行，转换后启用直接地址区

图 2 先受理指定不活动地址区的请求。原图 2 的 way B 有三条旧脏行，对应图 1 自上向下第 2、第 5、第 8 个 set。实施例发 flush 请求，将旧数据写回各自的系统内存地址。之后设置对应指示，使新地址区的访问可直达选中行。

转换前的 flush 是第 4、11、19 项额外限定。写回何时可确认安全、普通请求是否需要暂时阻止重分配，由实现规定。原图 4 区分普通缓存的写回与直接 RAM 的写入，直接 RAM 区自身作为数据端点，没有对应的系统内存后备地址。

启用后的安全检查与传输 QoS 分别处理

图 3 描述原图 6 的安全区实例，两名代理向同一活动地址发请求。缓存控制器根据系统内存映射识别目标是受限访问区，有权限的请求才访问对应存储位置。未授权事务被忽略，也可另外报告异常。

原图 5 的传输路径另有实时虚拟通道和 bulk 虚拟通道。绑定高优先级队列能改变获准次序，访问授权仍由控制器的安全检查判断。第 2 项是虚拟通道与优先级，从属于第 1 项。第 3、10 项涉及受限访问期收到未经授权的事务。

解除映射后，原 RAM 地址无效，way 回到普通缓存

看图 5 的请求位置。需要保留直接 RAM 的内容时，作业在解除之前负责复制到别处。控制器收到解除请求后清除标志，将行重新纳入普通缓存。这一步不会自行把直接 RAM 数据写回系统内存。

对解除后的旧地址，原图 8 举例读请求可返回默认值，写请求可报错。第 14 项限定返回默认值的读行为，第 7 项给出解除后访问错误。新来的普通回填可以覆盖重新启用为缓存的行。

直接 RAM 与预装系统内存缓冲的边界

表 4 比较两个同源说明书实施方式。本文的直接 RAM 实施方式会改写存储空间的用途。原图 9–15 的预装实施方式保留系统内存地址，对缓存填充次序进行调整，部分位置可能因冲突未驻留。这部分授权重点见同族 US11893251B2。

在手机 SoC 中评估直接 RAM，可以按同一作业访问轨迹记录转换的写回量、直接地址区的读写延迟和 QoS、其余缓存请求的 miss 与 DRAM 读写量。需要记录进入和退出该用途的时间边界，才能判断较短的作业能否覆盖转换成本。

    普通缓存预装与直寻址

    US11893251B2 保留系统内存中的缓冲区，通过非线性顺序把内容预装到普通缓存，再按缺失率调整顺序。US11704245B2 把部分缓存物理容量改作直接寻址 RAM，并将这些行排除在普通替换外。两种方式分别需要检查实际驻留与可分配容量。
