LLC 如何按序发出分散在多条流水线的设备请求

Request ordering in a cache

请求按地址与空项分散存放后，LLC 怎样找到某个 CPU 最早到达、仍未发给设备的严格保序请求？

核心结论

入口用设备地址选请求流水线，再按空项选该流水线的请求缓冲。请求内容写在缓冲。二级令牌记录跨流水线顺序，各流水线的一级令牌记录其内部缓冲顺序。发出端逐级读取队首，定位要发送的请求。

同一批请求的内容与定序信息分别保存

本件的设备请求包括访问有序存储区的请求。说明书把整个机制放在共享 LLC 的设备请求缓冲路径。按地址分流可把同一设备请求送到同一流水线。每条流水线再用空闲条目情况选请求缓冲（PRB），所以数据实际写入位置本身不表达发出顺序。

图 1 选择一条流水线和一个 PRB，分别绘出完整请求与两级令牌。二级 FIFO 按同一 CPU 的接收次序写流水线标识。一级 FIFO 仅记录落在该流水线的子序列。原图还为第二个 CPU 准备独立的一组令牌。图中 P1、B3 是站内示例名。

发出时先知道流水线，再知道缓冲位置

图 2 让请求 X 落在流水线 P1 的缓冲 B3。二级队首先选 P1。请求选择器再读取 P1 的一级队首 B3，从那里取出 X。在 FIFO 缓冲实现中可取相应队首。非 FIFO 实现可在一级令牌加入请求 ID，确保找的是 X。

独立权利要求 1、8、15 规定两级记录及用于发出。权利要求 2、9、16 更具体地限定最早请求。说明书允许两个层次的记录与缓冲选择在不同先后条件下执行。这里的顺序约束针对 LLC 把请求交给设备接口的时点。

有限重排走独立的一级令牌路径

同一个设备仍可能要求保序。原图 4A、4B 的有限重排路径为这些请求使用单独的一级令牌。按地址映射到不同流水线的有限重排请求可以独立成为候选，说明书允许用年龄、优先级或轮询等规则选一项。

当同条流水线的严格保序和有限重排请求都获选，说明书给出额外的本地选择器。它决定最终向设备发谁。表 3 分开队列如何产生候选以及候选最终能否发出。

连续队首决定同周期可发几笔

说明书 0037–0038 允许具备相应硬件带宽的实现同周期发多笔。先看二级队首相同的流水线标识能连续出现多少次，再看这条流水线的一级队首有多少连续项指向同一缓冲。两者的较小值是该缓冲本轮可考虑合发的数量，还要符合设备接受能力。

表 4 固定 B3 内两条请求。P0 若隔在两个 P1 之间，较新的 P1 请求仍要等 P0 发出。两个 P1 连续占据二级队首时才可当作同批候选。这个算例说明令牌位置为何必须同时满足，同周期最多能发出几笔由实现的接口宽度决定。

同一流水线的两类候选如何共享出口

原图 2 把严格保序与有限重排放在同一条请求流水线里。两组选择器可以读取该流水线内相同的请求缓冲。严格保序选择器还需要二级令牌选定本流水线。有限重排选择器使用单独的一级令牌，维持发往同一设备的顺序。

两组选择器可能同周期各选中一笔。原图 2 的本地发出选择器可用 FIFO、优先级或轮询择一。这个仲裁发生在二级队首所决定的严格保序候选已经产生之后。图 5 把共享的存储路径与两套定序入口展开。

请求缓冲按非 FIFO 实现时，令牌还要指到一笔请求

当 B3 是 FIFO，一级令牌只记录缓冲标识即可在发出时取该缓冲的队首。段 0031 还允许使用非 FIFO 缓冲。此时缓冲位置本身不能指出哪一笔等得最久。一级令牌可附请求 ID，发出端读取 B3 与 ID 后才能定位请求。

图 6 设 X 是根据两级令牌已经选定的最早请求，在 B3 中另有请求 Y。两个条目的物理位置仅用于说明 ID 如何约束选取。该机制可支持不同的缓冲组织，而访问延迟取决于实现的索引或选择方式。
