宽 load 按原子元素检查转发来源

Decoupling Atomicity from Operation Size

工作机制

成对或向量 load 的访问宽度可覆盖多个 ISA 原子元素。要判断是否可转发，先看每个元素字节对应的数据来源。

加载/存储单元（LSU）按原子元素验证整组字节取自同一笔 store 或另一完整数据源。不同元素可有不同来源。发生原子性或操作顺序违例时，实施例以阻止完成或重放维护内存一致性约束。

  1. 译码形成宽操作

    一条 load 指令可译为比原子性粒度更宽的内存操作。

  2. 并行寻址到数据缓存

    缓存路径给出正常数据，LSU 同时核对存储队列可转发字节。

  3. 逐元素确认来源

    按原子性尺寸分组，判断是否每组都完整来自一笔 store 或另一来源。

  4. 处理部分覆盖和顺序冲突

    阻止有混合来源的元素完成。权 17 的重放路径涉及 ROB 位置与按序发出。

示例

初始条件
一条配对 load 有两个原子元素 A、B。A 的所有字节来自同一笔较早的 store，B 的所有字节来自缓存。
处理结果
LSU 按元素确认 A 和 B 各自完整后才允许转发。
结果解读
若 A 的部分字节来自旧 store、其余来自缓存，须额外处理。元素边界和缓存行边界各自独立。

工程图解与对照

  • LSU 在宽操作内检查原子元素
  • 来源验证早于 load 完成
  • 不同来源的元素能否转发
  • 配对 load 中两个元素的对照

收益与代价

何时有效
在内存顺序模型允许时，可保持较宽的单次 LSU 访问与转发。
代价和限制
跨缓存行、字节掩码不齐和多微操作分解会增加验证与重放成本。
验证指标
按元素宽度和地址对齐分组，测 load 重放率、转发成功率及结果可用的周期。

权利要求与出处

独立权利要求为第 1、10、17 项。下方列出部分权利要求的中文释义。

权 1
每个原子元素必须完整来自单笔 store 或另一数据源，整个 load 才通过转发核对。
权 2
如果有元素混合取数且另有元素来自存储队列，可阻止该 load 完成。
权 17
发现顺序违例时冲刷流水线，靠近重排序缓冲区队首时按序执行产生该操作的多个 load。
