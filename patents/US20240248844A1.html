宽 load 按原子元素检查转发来源

Decoupling Atomicity from Operation Size

一条访存操作比 ISA 所需原子性粒度更宽时，存储队列的转发边界在哪里？

工程要点

LSU 在执行宽 load 时逐个验证原子元素，确认每个元素的全部字节均由同一笔 store 或另一完整数据源提供后，才允许存储队列转发。

成立条件
操作宽度大于原子性粒度。不同元素可来自不同源，但单个元素内部若混合覆盖，相关转发资格不成立。
验证方法
保持 load 地址、对齐和宽度相同，把 store 覆盖从完整原子元素改为部分元素。跟踪各字节数据来源、转发许可、重放次数和 load 的完成时点。

工作机制

成对或向量 load 的访问宽度可覆盖多个 ISA 原子元素。要判断是否可转发，先看每个元素字节对应的数据来源。

加载／存储单元（LSU）对宽 load 逐原子元素校验来源。每个元素必须完整来自一笔 store 或一个其他来源，元素间可以不同。跨缓存行和同一指令拆出的多个 load 还分别受定序校验。

  1. 译码形成宽操作

    一条 load 指令可译为比原子性粒度更宽的内存操作。

  2. 并行寻址到数据缓存

    缓存路径给出正常数据，LSU 同时核对存储队列可转发字节。

  3. 逐元素确认来源

    按原子性尺寸分组，判断是否每组都完整来自一笔 store 或另一来源。

  4. 处理部分覆盖和顺序冲突

    阻止有混合来源的元素完成。权 17 的重放路径涉及 ROB 位置与按序发出。

权项与实施例约束

权 2、3 允许阻止宽 load 完成，直到所涉及的 store 从存储队列排空。权 4、5 分别把原子性大小与目标寄存器大小或向量元素大小关联。

文中术语
原子元素
内存模型要求一次从完整来源读取的对象，其粒度可以小于执行操作的总宽度。
ROB
重排序缓冲区。保存待退休的指令，队首对应最老的一项。

图解与对照

  • LSU 在宽操作内检查原子元素
  • 来源验证早于 load 完成
  • 跨行定序违例后，由 ROB 决定是否强制顺序
  • 允许元素间异源，逐个检查元素内部

收益与开销

元素级检查在转发许可之前完成。它可以让各完整元素使用不同来源，但一处不完整覆盖会把整条宽 load 的等待延长到 store 排空阶段。

边界场景

同一宽 load 若在相邻迭代中交替遇到按元素宽写入和逐字节更新，前者可转发，后者可能要等相关 store 排空。整体缓存命中率相同时，完成时延仍可能分成两簇。

条件推演

初始条件
一条配对 load 有两个原子元素 A、B。A 的所有字节来自同一笔较早的 store，B 的所有字节来自缓存。
处理结果
LSU 按元素确认 A 和 B 各自完整后才允许转发。
结果解读
若 A 的部分字节来自旧 store、其余来自缓存，须额外处理。元素边界和缓存行边界各自独立。
