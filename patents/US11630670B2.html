用两种控制流签名预测指令缓存缺失

Multi-table signature prefetch

同一个 taken branch 可从不同调用路径进入，如何提前取回正确的指令缓存行，同时减少为相同目标重复训练的表项？

核心结论

CPU 前端分别维护两种签名，可用 taken branch 给出短签名，用 call 和 return 给出另一种签名。当默认表已有命中、仍出现缺失时，可用后一种签名训练另一张表。运行中两表可同时用于预测。

分支目标相同的路径可以有不同调用历史

0046、0048–0049 以移动 SoC CPU compute complex 为例，说明这些预取表可进入执行 OS 与用户态程序的 CPU 前端。0055–0056 列出手机应用。权利要求具体落在处理器流水线和控制转移签名的生成与训练。

图 1 将短签名和调用历史签名画成两条独立更新和查询路径。说明书以 taken branch 和 call／return 两组样本为例。尤其在调用路径汇合后，单个 branch 目标可能无法区分后来取不同指令的路径。长历史可以区分一部分路径，也会把访问同一目标的历史分到多个表项。

图 2 从实际缺失解释默认表命中为何会换表。当表已有相同 tag，而缺失的地址和已覆盖目标不同，继续训练同一签名可能让多个目标争用同一个表示。改用另一类签名可降低这种冲突。一次训练写一张表，平时查询可读两张。

表项命中门槛和训练去重各控制什么

图 3 分开两个门。训练地址靠得过近时可抑制两表。每一张表还可根据近期训练签名独立抑制。其后默认表的 tag 命中门槛用于选择训练位置。第一表未被选中、第二表未被抑制时，可训练第二表。

每表可用组相联结构，把签名的一部分用作索引，另一部分用作 tag。说明书还允许一个表项覆盖多个邻近目标、按目标维护计数，以及在同签名同目标的情形合并训练。

预取指令行与预取控制转移目标影响不同前端等待

图 4 连接两类预取目标。指令缓存若较早填到目标行，可减少随后取指缺失。下一取指预测器若较早得到控制转移目标，可更快选择后继取指地址；其训练触发可以是预测失败。

评估时将表容量、索引和预取带宽固定，分别记录训练写入、过晚到达、使用前逐出，以及提前供给 CPU 前端的缓存行。下一取指预测器的目标准确率单独统计。原文允许调高签名预取行的插入优先级，这也可能增加对其他活跃行的替换压力。
