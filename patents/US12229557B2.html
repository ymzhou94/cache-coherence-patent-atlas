核心结论

原子预测器提前判断条件写是否会执行。预测写入时可投机转发或争取 exclusive。预测不写时可延迟 load、取缓存旧值、请求 shared 或让上游节流。实际提交仍由原子操作规定。

同址命中之后还需知道条件 store 是否会提交

0022–0024 将预测器放在 CPU LSU，0091 明确手机 SoC 可实现该 CPU，0092–0093 给出手机及低功耗 DDR 实施例。独立权项覆盖 CPU 流水线电路的预测及功耗控制。

CAS 读取旧值并比较，只有比较满足条件才写回。若年轻 load 与条件 store 同址，store queue 即使有新数据也未必可安全交付。图 1 连接预测与状态发送点。store queue 可把预测和待写数据一起存放。

图 2 表示错误转发的代价。预测会写且转发新值后，真实比较失败，使用了错误数据的 load 及后续执行需要恢复。预测失败时可等相应 store 离队，然后重放 load 并从 data cache 读。说明书还允许部分设计更早投机读 data cache。

按实际完成和是否发生转发调整预测

图 3 比较全局计数与索引表。全局历史会把不同原子操作合并。按 PC 等信息索引可分开不同调用点的偏向。碰撞、初始化和执行阶段切换都可能降低精度。

实施例着重惩罚导致错误转发的失败，未转发的数据可按同权重、较低权重或不更新处理。权利要求 6、10、19 用 written 描述附加条件，说明书的更新图用 forwarded。对照原文保留两种表述，区分条件写提交与投机转发。

权限申请、数据转发和上游节流应分别计量

图 4 从 CPU 内部预测接到一致性。提前取得 exclusive 可减少实际写入的升级等待；正确预测失败时保留 shared，可以少发一次不必要的升级。独权 1、9、17 的共同限制是用失败预测降低流水线功耗，两个缓存状态及数据转发是在部分从权中加入的。

在 OS 同步原语和用户态运行库中，可用相同地址的负载构造成功或失败偏向阶段，量出流水线恢复、已取消的转发、年轻 load 重放，以及一致性权限请求。控制变量应包含竞争核心数及队列深度。
