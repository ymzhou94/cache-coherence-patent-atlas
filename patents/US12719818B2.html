集中处理 AP 的非 DRAM 事务与流控

Centralized non-system-memory gateway circuit

CPU 只接自己的片上网络时，怎样访问另一网络上的寄存器或设备，同时减少各端点网络接口的路由缓冲？

  • 核心结论
  • 设备寄存器访问不占用 DRAM 数据路径
  • 入口背压与目的端等待各有独立资源
  • 寄存器广播需要汇集每一份目标应答

  • 关联专利

核心结论

CPU 与 I/O 的普通 DRAM 请求仍各走内存路径。跨网络的非 DRAM 请求先由 NSM gateway 接管，在入口按源缓冲、按目标地址排到出站队列。源网络信用可较早归还，目的端交付和响应另计。

设备寄存器访问不占用 DRAM 数据路径

0010、0019–0024 与原图 1 描述手机 SoC 场景中 CPU、内存控制器和显示/ISP 等 I/O 代理，独权明确 CPU 只接第一网络，并由 NSM gateway 处理 AP 内非 DRAM 事务。

原图 1 把 CPU 网络、I/O 网络、内存控制器和 NSM gateway 放在同一个 SoC。图 1 分出两条 CPU 请求路径。内存读写送内存控制器。若只是修改该控制器的配置寄存器，目标同样是内存控制器，但不访问 DRAM，仍可通过 gateway。

两端的网络接口（NI）可只为 gateway 保留路由存储。集中后的地址解码同时处理同网或跨网目的端。权利要求 9 还保留第一网络上某些缓存一致性操作的直达路径。

入口背压与目的端等待各有独立资源

按源的入口缓冲保存已受理消息，地址解码查映射表。每个目的网络可按目的端建立出站队列。图 2 展示某一目的端暂缺信用时，另一目的端仍可参与出站仲裁的情况。

图 3 分开观察源信用和真实响应。gateway 的入站 NI 接管请求后可归还源段的信用。此时目的端可能尚未收到消息。请求仍须经过目标队列、目标 NI、设备处理和回程。

寄存器广播需要汇集每一份目标应答

图 4 使用原图 6C 的 CPU 写配置空间例。网关识别广播地址，事务管理器向两个内存控制器转发请求。两个响应都回到事务管理器后，才发送合并响应。读广播还可以在管理器聚合读回的数据。

集中路由有望降低各端点所需的目的专用缓冲。单个 gateway 的结构容量和出站速率也可能成为瓶颈。测量时区分源 credit 归还、目标收包与完整响应三条时间线。
