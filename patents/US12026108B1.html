带宽很低时，访存延迟也能触发缓存升档

Latency-based performance state control

CPU 只有少量在途请求时，共享缓存怎样识别串行访存已经拖慢执行？

核心结论

对可调频的缓存层级分别生成带宽和延迟运行点请求。低并发访问的延迟够高时，延迟路径可单独请求升档。状态控制器再综合两个请求决定缓存运行点。

分别处理带宽和延迟反馈

原图 8 给出电池供电的移动 SoC。说明书归档段 0049–0053 明确，AP 的 CPU complex、GPU 或两者可以提供延迟信息，缓存／内存控制器据此调节 memory cache 的性能状态。

请求量小的依赖链也可能被加载延迟限制。图 1 把缓存运行点控制画在 AP 的返回路径之外。CPU 或 GPU 提交请求并观测响应，带宽和延迟控制器提出各自的运行点，再由状态控制电路更新指定的缓存层级。

原图 3 的低并发、高延迟情况允许延迟请求抬高缓存运行点。高并发的两个示例交给带宽路径。权利要求 5 进一步限定选择两路请求中较高的一档。说明书对其他实施例允许加权或逻辑合并。

确认慢的是哪段访存路径

图 2 的两个商使用同一窗口的请求时长。平均延迟以请求数为分母，平均在途量以窗口的处理器周期数为分母。只统计 fabric 往返时间的实施例，应在该边界记录请求入网和响应出网，量纲和时钟域需对齐。

在一个 1000 周期的示意窗口内，4 笔各 100 周期与 20 笔各 20 周期都累加到 400 请求周期，平均在途量同为 0.4。平均延迟分别为 100 和 20 周期。若延迟阈值为 60 周期且在途阈值为 1，只有前一组满足升档条件。

图 3 比较同一批观测值经过两种直方图后的信息。按延迟区间计数可回答高延迟请求占多少。按时间子窗给均值可以看出何时变慢。若关注由少量慢请求引起的尾延迟，需要保留延迟区间计数或等效的分布信息。

升档和降档的窗口长度由谁选择

图 4 将升降档窗口并排。短窗口使升档请求更早进入裁决，较长的降档窗口可减少短间隔引起的反复切换，也会增加高运行点驻留时间。专利以 M 与 N 个历史窗口描述这个约束，具体窗长可配置。

验证时同时记录该缓存的实际运行点、请求发出到响应返回的时刻、每周期在途量及电源轨能量。若慢请求主要等待下游 DRAM，提高被控缓存时钟的收益可能有限。
