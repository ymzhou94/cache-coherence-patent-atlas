sticky 分配按数据流组保护驻留缓存行

System cache with sticky allocation

系统缓存收到 sticky 提示后，什么时候分配为 sticky？别的组访问已经 sticky 的行，能否改变它后续的替换归属？

  • 核心结论
  • 请求提示和驻留 tag 状态是两个字段
  • 带 sticky 提示的 miss 可以新分配，命中普通行维持原状态
  • 候选查找先普通，再受控地看同组 sticky
  • 跨组 sticky 命中可以在原位置更新归属
  • 保留的收益取决于跨较长间隔的实际重用
  • 权利要求与出处
  • 关联专利

核心结论

请求带 group ID 和 sticky 分配提示。遇到 miss 时，控制器可按候选规则分配 sticky 行。若命中普通行，它仍保持原状态。若命中另一组的 sticky 行，实施例允许更新其 group ID，在原位置继续保留数据。

请求提示和驻留 tag 状态是两个字段

图 1 从代理请求追到系统缓存。group ID 表示数据流，既可以由多个代理共用，也可以让同一代理的不同流使用各自组号。原图 5 的请求字段还有地址、事务 ID 和分配提示。

控制器用地址在 tag 阵列命中对应 way。tag 存实际的 sticky 状态和 group ID。逐组配置寄存器可另外记录 quota、活动状态及是否允许同组替换。原图 1 的一致性点（CP）是 Apple 说明书的路由模块。

带 sticky 提示的 miss 可以新分配，命中普通行维持原状态

图 2 上半部是一笔 X 缺失。存在可替换的 non-sticky 位置时，控制器将 X 在该位置分配为 sticky，并登记请求组号。下面的 Y 本来已经驻留且状态为 non-sticky。新请求虽带 sticky 提示，Y 仍按普通行处理。

授权第 1、8、14 项明确覆盖命中后保持 non-sticky 的行为。有提示的访问不自动把每个命中的副本都加入保留集合。请求本身的 sticky 取值与阵列中的实际 tag 状态应分别观测。

候选查找先普通，再受控地看同组 sticky

图 3 展开原图 8。优先查找可用的 non-sticky 位置。没有时，读取请求组的 sticky replacement 配置。只有配置允许且确实找到该组的 sticky 候选时，才可用这条同组路径。其他组的 sticky 行不能仅因为本组缺失而替换。

四例复算候选：存在普通候选时直接采用普通位置；没有普通候选但同组允许且有候选时采用同组位置；配置关闭或只有其他组 sticky 时，都不在系统缓存分配。数据仍可从内存返回。第 9、10 项规定同组配置对替换的控制。

跨组 sticky 命中可以在原位置更新归属

图 4 的地址 X 已 sticky，原组为 A。B 组发出带 sticky 提示的同址请求时，tag 命中。控制器可以把其中的 group ID 改为 B，数据仍在同一个 way，sticky 状态也继续生效。组号变化会改变以后的同组替换资格。

授权第 7、16、20 项描述这项变更。第 12、13 项另写软件命令可批量转移组号，它也可以涉及 non-sticky 行。说明书将相邻渲染帧共用边界数据作为例子，使用权的迁移是缓存替换组归属的更新。

保留的收益取决于跨较长间隔的实际重用

可按不同 group ID 记录 sticky 的占用、被保护后下一次重用的间隔、替换失败、转组次数和下层内存读写量。已有普通候选减少时，其他流的缓存分配机会会发生变化。可使用相同的请求流和同组替换配置比较两种结果。
