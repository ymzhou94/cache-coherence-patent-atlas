核心结论

关键性选择一套插入／提升向量（IPV）。命中用当前 rank 索引 P 元素，回填使用 I 元素。更新电路再根据目标 rank 生成掩码，让各位置保持、接收相邻位置的记录，或放入被移动的行。

先选策略，再根据事件读向量元素

图 1 中，命中可以从标签拿已保存的关键等级。缺失回填时，控制器按请求来源及队列条件定关键性。选择器据此从时钟存储元件中选一套 IPV。可以为不同等级分配不同向量，也可以共享。

一套向量包含每个当前排名的 P 元素和专用于回填的 I 元素。命中时才有当前 rank，例如命中 rank 3 就查 P3。回填没有当前 rank，读取 I。原图 4A 的 LRU 向量把 P 与 I 都设为 MRU，原图 4B 示范不同目标，甚至可让命中的行靠近逐出端。

多路选择器如何更新一组替换数据

图 2 放大组内一个排名位置 i。P/I 掩码标出唯一要直接接收当前行的位置。移动掩码标出其余需要挪动的位置。比较目标与旧位置，生成表示移动方向的位。

从图左侧逐项看，位置 i 可以接收 Wi−1、保持 Wi 或接收 Wi+1。P/I 置位时选当前命中／填入行的替换记录。每个位置有相应选择器，各自算完后形成同一组的新顺序。命中更新的是替换记录。缓存行数据并不随这些小记录的更新而在物理路之间交换。

沿着一笔 rank 3 命中跟踪每个位置

图 3 采用原图 4B 的 P3=1，只展开受影响的前四个排名。D 命中前在 rank 3。P/I 选择让 D 写入 rank 1。rank 2、3 的移动掩码打开，各自填入旧的左邻记录 B、C。rank 0 的 A 不动，更靠近逐出端的其他位置也保持原有顺序。

换成原图 4A 的 LRU 向量，D 则到 rank 0，A、B、C 都后移。若新位置比旧位置更靠近逐出端，受影响的记录往另一方向移。例如原图 4B 的 rank 5 命中可以降到 rank 6。两幅原图都以 rank 0 表示 MRU。

近远分区让排名变化可能带来数据搬运

基本的 IPV 更新针对组内排名。若实现有访问延迟不同的 near／far 分区，排名还可能决定数据留在哪个物理分区。图 4 展开这个可选实施例。排名在原分区内移动时可以只改替换状态。跨分界时才会产生相应数据移动。图中的 C 进入 near 后，原先的 B 被推到 far，因而跨界的有两条行记录所对应的数据。

选择向量时，关键性判断错误可能让低复用行进入高保留位置。表 5 固定总访问和逐出端，只改向量分配，观察 A、B 能否保留。模型不计算分区迁移。若评估分区实现，还需分别记录跨界搬运量、近端命中与远端命中延迟。

授权范围与可编程策略的关系

独立权利要求 1、9、16 关注按关键性选择存储的 IPV 并更新替换数据。权利要求 2、10–12 分别写入排名元素与插入元素的用法。不同关键等级可以各有向量，也可共享。near／far 分区及搬运属于说明书举出的实现条件。

  • 机制对照 US11921640B2

    何时停止优先保留已经不再关键的缓存行

    用关键性更新排名与退出保护

    US12222875B1 先按缓存行的关键性选 IPV，再用旧排名查新位置。旧排名相同的行也可能因关键性不同而获得不同的新排名。US11921640B2 另用关键行命中率等信号决定何时停止优先保留。退出后继续使用独立的替换数据。

  • 机制对照 US11144476B2

    多端口缓存怎样合并同组 LRU 更新

    选更新对象与选新排名

    多端口缓存同拍命中同组两路时，先比较两路旧排名与阈值，让控制器决定本次更新哪一路。IPV 方案针对已经确定的访问行，按该行关键性选向量，再由旧排名查新排名。一个解决同拍写替换状态的争用，另一个定义这次更新的幅度。
