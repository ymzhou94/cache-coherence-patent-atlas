工程要点

替换控制器按被访问行的关键性选择插入／提升向量，再据所选向量更新替换排名。

成立条件
命中时向量按旧排名指定新排名。填充时使用向量规定的插入位置。
验证方法
固定访问轨迹、关键性标签和初始排名，以所有行使用同一向量为对照。记录同一旧排名的提升目标、移动范围，以及各类行下次被选为逐出对象的顺序。

工作机制

普通 LRU 将命中的行提升到同一位置。这里，同为旧 rank 3 的两行可以因为关键性不同，得到不同的新排名。

替换控制器根据本次访问所涉缓存行的关键性选一套插入／提升向量（IPV）。向量为每个旧排名指定提升位置，也给新行指定插入位置。部分实施例还在向量中给出逐出位置。

  1. 确定访问的关键性等级

    缓存给出命中结果和位置，关键性电路判断此次访问涉及哪一等级。实现可以只分关键与普通，也可设置多个关键等级。

  2. 查找相应的 IPV

    控制器从时钟存储元件中取出该等级的向量。向量包含各旧位置的提升值和新行的插入位置，有些向量还包含逐出位置。

  3. 命中查 P，填充查 I

    命中时用旧 rank 索引 P 元素。缺失需要填充时，取 I 元素决定插入位置。图 4A 把 rank 0 定为 MRU。图 4B 中，从 rank 3 命中的行可以停在更低的位置。

  4. 写回排名

    主条目换位后，控制器相应更新新旧位置之间各行的相对排名。图 6 用掩码和多路选择器生成新的替换数据。

权项与实施例约束

权 2、3 为提升和插入分别定义向量元素。一个有效命中要用该行的旧排名索引提升元素，缺失回填才用额外的插入元素，这两个索引来源不同。

工程推演与验证

收益与开销

对一套向量来说，提升位置与旧位置越接近，更新需要经过的排名区间就越短。可单独比较状态位翻转和逐出选择，避免用总体命中率掩盖两项变化。

边界场景

一条反复被访问但错误标为普通的行，如果每次只提升一位，可能在两次访问之间被同组的填充逐出。这样的轨迹可单独暴露保守提升的代价。

条件推演

初始条件
假定 rank 0 至 3 依次是 A、B、C、D。D 在 rank 3 命中，用图 4A 和图 4B 的规则分别更新一次。
处理结果
按 LRU 示例，D 升到 rank 0，顺序变为 D、A、B、C。按非 LRU 示例，D 只升到 rank 1，顺序为 A、D、B、C。
结果解读
算例把列表缩为四项。两个目标 rank（0 和 1）沿用说明书示例，更新时各行仍留在原来的物理 way。

专利原文

关联专利

  • 停止优先保留不再关键的行

    同一缓存行的旧排名保持不变时，关键性仍可使控制器选用不同的插入或提升向量，改变它在下一次逐出时的位置。另一件专利跟踪被标关键的行有多常命中，低于门槛时退出优先保留。前者定义标记如何影响排名，后者定义何时停止信任这批标记。

  • 多端口缓存的 LRU 排名更新

    多端口缓存同拍命中同组两路时，先比较两路旧排名与阈值，让控制器决定本次更新哪一路。IPV 方案针对已经确定的访问行，按该行关键性选向量，再由旧排名查新排名。一个解决同拍写替换状态的争用，另一个定义这次更新的幅度。
