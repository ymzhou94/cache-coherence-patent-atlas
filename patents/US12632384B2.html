I/O agent 提前取权限，按外设顺序完成

I/O agent

两个外设读请求必须按 A、B 完成。如果 B 的独占读访问权先到，I/O agent 如何利用这个返回顺序缩短后续等待？

核心结论

I/O agent 代无缓存外设请求并暂存缓存行。它允许后到事务先得到权限与数据，等先到事务完成后再从本地服务后到事务。如果等待时收到 snoop 并放弃权限，原先取回的数据便不能继续用于完成请求。

哪些硬件持有外设可用的数据副本

图 1 从外设请求开始。外设通过 I/O agent 访问一致性互连。I/O agent 能向管理目标地址的内存控制器请求独占读访问权（exclusive read ownership），并把取回数据留在自己的已取回数据缓存。专利所称独占读访问权要求缓存行的数据在内存和该 I/O agent 之外没有有效缓存副本。

图中控制器的目录指示其他缓存代理是否持有有效副本。命中时，一致性控制器发送所需 snoop 并处理响应。图 1 采用由缓存代理返回控制器的 snoop back。说明书也给出数据由持有者直接发到请求方的 snoop forward。两种路径中的响应、数据和权限消息要分别读。

B 的权限先到，外设为什么先收到 A

图 2 采用原图 4 的请求 A、B。A 的目标行在另一缓存代理里，A 所属控制器需要 snoop。B 的目录未命中，B 所属控制器可在不等该类 snoop 的情形下返回许可和数据。表 3 比较本例两个目录结果产生的额外路径。

I/O agent 先保存 B 的许可和数据。A 完成后，若 B 的许可和缓存行仍有效，就能直接在 I/O agent 内完成 B。省去的是在 A 完成之后重新启动 B 取权限的等待。外设看到的完成仍然先 A 后 B。该顺序由外设的事务约束和依赖决定，与 CPU 的内存序模型分开。

部分写输入如何与取回的原行合并

图 4 返回到 I/O agent 内部。取得独占写访问权时返回的原行进已取回数据缓存，外设带来的新字节先进新写入数据缓存。两个来源分开保存时，合并前的 snoop 可读取当时有效的旧数据而没有混入尚未生效的外设写。

事务排到最早且权限仍然有效时，控制器才合并本次写入字节与未覆盖的旧字节，结果进合并数据缓存。说明书中的整行写可以有不同的数据返回条件。授权权利要求 7、19 明确描述保留部分未覆盖数据的情形。

预取行被 snoop 后，什么时候重新向互连请求

图 5 展开说明书的边界条件。I/O agent 在完成先到事务之前，可能收到针对已在本地暂存的缓存行的 snoop。放弃权限后本地行失效，此时已完成的预取不能推进剩余读请求。控制器按同一行的待处理请求数量以及可选的队列位置判断是否重新申请。

¶0048 的实现达到数量阈值会重取独占读访问权。少于阈值可以处理余下读而不先重取独占权，权利要求 4、5 组合描述该分支。性能取决于取权限与前序执行实际重叠多少、被 snoop 撤销概率、相同缓存行合并数量以及额外竞用。

授权权项中的发出、取得和完成顺序

第 1、10 项明确要求先发第一条读的独占读访问权请求，后发第二条，随后第二条的权限先于第一条取得。第 2 项另写明设备读请求按第一条、第二条的次序完成。第 15 项针对可用于制造的电路设计信息，另要求获得至少一个写请求的独占写访问权。

说明书以取回缓存行超过 500 个时钟周期举例，计时对象是取行的等待。工程对比可分别测设备读请求到退休、取得权限到实际使用的等待，以及缓存行由于 snoop 被过早释放的比例。文献没有为这三个量给出产品测试结果。
