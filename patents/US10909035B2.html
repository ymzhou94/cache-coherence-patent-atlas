L2 容量为零时，控制器仍负责回填与 snoop

为了减少片上存储面积而省去 L2 缓存阵列之后，控制器怎样处理 L1 缺失？如果 L1D 还持有最新的数据，能直接去下游取吗？

零容量配置保留 L2 控制器的请求、响应及协议路径。可缓存缺失可以从下游回填 L1，L2 不留副本。当前访问不可缓存、指令侧缺失或收到外部 snoop 时，部分路径还要按物理地址检查 L1D。

保留上下游接口、请求队列和响应队列

图 1 把可选 L2 阵列与控制器分开。配置与状态寄存器（CSR）指明阵列是否存在。零容量实现跳过同层缓存接口和缺失队列，保留向 L1 与下游存储收发消息以及管理请求与响应队列的逻辑。控制器名字仍叫 L2 是因为其在原设计中位于 L1 和下游之间。

对普通可缓存 L1D 缺失，控制器把请求发往 L3 或系统内存，再把返回数据送回 L1。说明书原图 5 给出的可缓存 store 路径，还会在送回前把 store 字节合入返回数据。L2 阵列没有参与这一过程。

不可缓存访问也可能遇到 L1D 中的副本

说明书用两个虚拟地址说明问题。早先的可缓存映射将物理地址 P 的缓存行放进 L1D。后来另一映射同指 P，本次访问却带不可缓存属性。图 2 的控制器用 P 发 snoop，查有没有还留在 L1D 的旧映射副本。这个例子按专利描述的映射处理条件理解。

snoop 命中后要先取数据，再使副本失效。返回的是脏行时，控制器发出 writeback。若查找缺失，由下游存储提供数据。回送的 load 数据带不可缓存指示，L1 不为本次读取分配缓存行。

部分 store 只覆盖目标字节，先选对旧行

图 3 继续用同一物理地址。L1D 命中就用它返回的缓存行，缺失才从下游取旧数据。控制器用 store 的字节范围做合并，然后把合并后的数据发到下游。完成信息回送 L1D，并保留不可缓存属性。

四字节模型中，下游仍存 a b c d，L1D 中最新的脏行是 a b c z。若 store 把中间两字节改为 X、Y，跟随图 3 的命中分支会写入 a X Y z；绕过 L1D 会写入 a X Y d。两条路径只改了合并输入，未写字节就能出现差异。

取指缺失与远端 snoop 有各自的入口

图 4 说明自修改代码的示例。取指在 L1I 缺失后，L2 控制器从数据侧发起查找。L1D 命中则取回最新指令字节，必要时发下游写回，最终允许 L1I 回填。数据侧也缺失才读下游。说明书描述的是这一控制器的行为，软件使用的指令缓存维护规则仍取决于具体 ISA。

图 5 的事务由远端发起。L2 跳过本层查找，把带完整地址的 snoop 转发至 L1D，再依据 L1D 的响应答复发起方。这一路并不要求有本地 L1 缺失来触发。

三个独立权项 1、10、17 写的是收到较高层缓存不存目标数据的指示后发 snoop。零容量同层的禁止填充条件见从属权项 4、12、19。图 4、5 说明的是说明书所列的另外两种具体请求路径。
