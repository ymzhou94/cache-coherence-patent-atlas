中间缓存容量为零时仍保留控制路径

Processing memory accesses while supporting a zero size cache in a cache hierarchy

工程要点

中间控制器接到指令侧缺失后，仍可用完整地址探测上层数据缓存。零容量配置跳过本地数据阵列。

成立条件
指令侧缺失与数据侧是否持有副本是两项判断。图 9 的数据侧命中可能返回较新的指令。
验证方法
固定指令地址和中间层零容量配置，输入只有下层副本及 L1 数据缓存还存较新副本两种状态。记录上探次数、下层补读次数和返回给指令侧的数据版本。

工作机制

L1 指令缓存报告缺失时，L1 数据缓存仍可能保存修改过的指令。中间层即使没有数据阵列，也需要分别检查这两条路径才能选对数据来源。

中间控制器保留上、下层接口。收到特定的上层缺失指示后，它还能向上层发 snoop，再按探测结果从上层取数据或向下请求。说明书的零容量配置省去了本地数据阵列查询和回填。

  1. 省去本地阵列，保留控制器

    说明书支持本层有阵列或无阵列。零容量配置跳过本地查询及分配，继续运行上下游接口和事务控制。

  2. 按完整地址向 L1 数据侧探测

    收到上层缺失指示后，控制器按所需地址发 snoop。图 9 中，最初是 I-cache 缺失，后续按完整地址查 L1 D-cache。

  3. 根据探测结果选数据源

    上层命中时，控制器可能先取数据，再决定是否写回或失效。上层也无数据时，向下层发请求。本层没有阵列可以接收回填。

  4. 按事务类型回送结果

    图 9 的取指路径中，D-cache 命中脏指令后，可把副本送往下层，再响应 L1 指令侧。图 8 的外部 snoop 则向上传送，并按上层的回复作答。

机制约束

权 2 把上行探测未持有数据作为发下层请求的依据之一。权 4 则明确下层回来的填充可以不存到同级缓存。控制器保留了事务取数，省去相应数据分配。

图解与对照

  • 指令缓存缺失后查 L1 数据缓存
  • 零容量中间层仍连接上下游
  • L1 数据侧未命中、干净命中或脏命中
  • 有本地阵列与零容量时分别经过哪些路径

实验与取舍

收益与开销

中间级不写回填阵列，能省本地存储端口和容量开销。上行探测的请求、回复和必要的一致性动作仍会占用上下游接口，较低容量不直接减少这些消息。

边界场景

若短工作集反复访问已不在上层的同一批行，零容量中间级无法留下最近的下层回填。上行探测都找不到时，重复下层取数可能抵消省去本地数组的成本。

条件推演

初始条件
在图 9 的零容量配置下，假定 I-cache 查地址 X 缺失，内存仍存指令旧值 7，L1 D-cache 中存更新后的值 9。
处理结果
中间控制器向 D-cache 发完整地址 X 的探测，并在命中后取得 9。示例中，控制器处理脏状态时先把副本送往下层，再向 L1 指令侧返回所需数据。
结果解读
7 和 9 用来标明新旧版本。这里采用的是图 9 的取指和探测顺序。具体的自修改代码同步仍须遵守其运行环境的规则。

说明书图 8–9
外部 snoop 可以绕开本层阵列。取指缺失时先探测 D-cache，结果决定是否取脏值或向下层请求。

关联专利

  • 空闲核的存储阵列失效维护

    两件专利都把数据阵列和一致性操作分开。零容量中间层继续转发探测，取指缺失时仍可查上层数据缓存寻找最新值。空闲核方案面对的是仍保存条目的阵列，由 PMU 记下失效，恢复执行前处理。取数依赖探测返回，空闲阵列的失效则可推迟到唤醒边界。
