把二级 trace cache 的轨迹提前送到前端

Hierarchical Trace Cache

较长的指令轨迹留在远端缓存时，怎样使二级命中赶在前端需要之前返回？

工程要点

二级轨迹缓存的预取结果先放入缓冲，前端消费后再按相应执行指标决定是否把轨迹提升出缓冲。

成立条件
预取预测须能找到已存的轨迹。能否缩短等待取决于返回是否早于需求，提升还要看执行反馈。
验证方法
固定循环轨迹、二级读取延迟和预取预测序列，对照缓冲消费即提升与按执行指标提升。记录实际消费、提升和一级热轨迹逐出的次数，再看前端供给等待。

工作机制

分层 trace cache 可把容量和访问延迟分开。若等前端一级缺失后才访问二级，长轨迹仍可能晚到。

预取逻辑预测未来会执行的轨迹，从二级轨迹缓存向前端方向预取。原图 12 用路径签名实现前瞻，并让返回的轨迹进入快速阵列。采用执行反馈的从属方案，可以在供给后据使用情况决定是否晋升一级。

  1. 按地址路径预测候选

    签名来自执行路径上的指令地址。原文给出与历史签名异或的实现。

  2. 二级命中后写入预取缓冲区

    在较慢二级返回时，缓冲区接收轨迹而不急于替换一级条目。

  3. 前端消费

    前端到达对应路径时，可以直接使用缓冲区内已返回的轨迹。

  4. 决定是否将已用轨迹提升

    部分权项比较消费结果，按实际使用决定是否放入一级。

权项与实施例约束

权 3 用当前地址与上一签名异或更新路径签名，权 4 用该签名做多拍前瞻。权 17 还允许预取目标地址到下一取指预测器，与轨迹数据返回分开处理。

路径签名

收益与开销

地址预测器能提前知道目标地址，并不能让二级轨迹阵列立即返回。每次候选都要占读取和缓冲资源，评估时可把前瞻产生、目标地址可用及轨迹数据可用区分开。

边界场景

若不同分支历史在较短签名上相互干扰，同一个签名可能反复给出错误轨迹。即便二级都能找到这些轨迹，错误候选仍占缓冲，可能把随后实际需要的轨迹挤出。

条件推演

初始条件
同一循环的常用轨迹已进入二级 trace cache，一级中当前没有该轨迹。路径预测器提前识别出即将访问它的路径。
处理结果
二级查读在需求前启动。若轨迹先到预取缓冲区，前端可直接消费，之后再按指标决定是否提升。
结果解读
把轨迹命中、及时返回和实际消费分开计数，才能判断是否覆盖前端等待。

关联专利

  • 支持多种长度的分层 trace cache

    US12547409B2 为近层和远层规定不同的轨迹容量，预取缓冲能接收远层较长的轨迹并供前端执行。US20250315262A1 权 2 进一步规定预测所用的信息：由执行路径中的指令地址生成签名。两项分别聚焦于长轨迹的容纳与交付，以及启动二级预取时使用的信号。

  • 按页定位二级 trace cache 的失效范围

    US20260211681A1 的说明书首段指向申请 US18/626,929。母申请独权 1 描述用预测结果从二级轨迹缓存提前取轨迹，继续申请独权 1 处理维护操作到来时如何仅使部分二级条目失效。保留到下一次取指的轨迹需要继续满足地址转换和执行权限条件。
