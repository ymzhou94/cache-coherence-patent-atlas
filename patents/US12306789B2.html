按性能需求为同类型 CPU 核簇划分性能岛

Performance islands for CPU clusters

两个线程组需要不同性能时，怎样把它们放到同一种核型的不同核簇？

工程要点

性能控制器发现第一性能岛没有活动线程组时，可把其 CPU 核簇划给第二岛，再将第二岛的线程组重新布置到该核簇。

成立条件
两岛核簇为同一核类型，控制量范围不同。在此次重分配中，第一岛各核簇都没有已分配的活动线程组。
验证方法
回放相同线程组活跃时间和控制需求，对照固定核簇归属与空岛时重分配。记录重新放置次数、任务开始等待及迁移后的缓存缺失。

工作机制

性能岛是性能控制器管理的一组核簇及其控制量范围。相同核类型的两个核簇可以对应不同范围。

性能控制器按线程组控制量及性能岛覆盖范围确定放置，并可向 OS 调度器报告首选核簇。线程组可在不同岛运行，即使两岛的 CPU 核簇采用相同核型。

  1. 计算线程组控制量

    性能控制器采样活动线程组，并把控制量与定义好的范围比较。

  2. 选择同类型核簇中的性能岛

    需求较低的组可保留在第一岛，需求更高的组被指向覆盖较高控制量的另一岛。

  3. 通知调度器核簇偏好

    性能控制器更新首选核簇。调度器依据自己的运行条件决定线程实际放置。

  4. 按活动情况调整岛成员

    第一岛没有活动组时，可把其中的核簇转给第二岛，并重新分配线程组。

权项与实施例约束

权 1 关联两组控制量和两个性能岛，核簇共享同一核型。权 2 提供不同操作，第一岛没有任何活动组时可重分配岛成员。权 3 才增加此次重分配向调度路径发首选簇信号。

文中术语
性能岛（performance island）
性能控制器用于管理零个或多个 CPU 核簇的对象，覆盖一个预设控制量范围。
控制量（control effort）
性能控制器使用的无量纲值，用于给线程组表达性能需求。
首选核簇（preferred CPU cluster）
性能控制器提供给 OS 调度器的放置建议。实际可运行位置还由调度器判断。

收益与开销

共享同一电压域的两组可因更高需求而一起运行在较高频率。分开放置有机会减少低需求组的高运行点驻留，但要测迁移后每簇缓存缺失和线程完成时间。

边界场景

固定两组各自的工作量和控制量，逐步增大它们共享的工作集。若分组后原低需求组的运行点下降，而每单位工作量的能耗增加，应检查跨簇末级缓存流量和缓冲区共享。

条件推演

初始条件
原图 4 的线程组 E 控制量为 0.5，覆盖范围是岛 1。线程组 D 需要 0.8，覆盖范围是岛 2。两岛核簇都是 P 核。
处理结果
性能控制器为两组推荐不同核簇。E 仍可用原控制量运行，D 放到较高控制量范围的岛。
结果解读
0.5 与 0.8 是该实施例的无量纲控制量。核簇电压和频率驻留需要单独观测。

  • 非对称多处理器的闭环性能控制与热功率约束

    两案均按线程组控制量提出运行建议。US11579934B2 围绕核型及运行点给出建议，并在热约束下安排执行。US12306789B2 为同一种核型的核簇划分不同控制量范围的性能岛，使不同需求的线程组可以分别放置，同时保留第一组原有的控制量。

  • 按核簇共享资源饱和度迁移单个线程

    性能岛根据线程组的控制量给出首选核簇。实际运行时，若某一核簇的 BIU 请求队列持续饱和，US12147839B2 用 LSU 微操作指标设置线程标记，允许调度器只迁移相关线程。同组其他线程可以维持原来的核簇放置。
