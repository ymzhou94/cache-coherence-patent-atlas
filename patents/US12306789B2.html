按线程组需求划分同核型 CPU cluster 的性能岛

多个线程组都适合 P-core 时，怎样避免高性能需求把低需求线程组的工作电压一并抬高？

性能控制器把控制量相近的线程组放在同一个性能岛，再在岛内选首选 CPU cluster。不同岛可以使用相同核型的 CPU cluster，各自覆盖不同控制量区间。OS 调度器读取首选 CPU cluster 建议，决定线程的实际放置。

性能岛在共享电压域之间分离不同需求

在原图 3 的例子中，控制量 0.5 和 0.8 的线程组都满足 P-core 的条件。如果它们共用一个电压域，控制器为高需求组提高该 CPU cluster 的电压或频率时，低需求组也会在较高的状态运行。

原图 4 改用三个性能岛。岛按控制量范围接收线程组，岛内再选首选 CPU cluster。图 1 把每组的样本反馈、岛的范围和调度建议放在一起。控制量是无量纲性能需求，性能控制器可据此推荐动态电压频率调节（DVFS）运行点。

线程组自己的控制量如何传到 OS 调度器

原图 4 的例子中，控制量为 0.3 的 F 组归入岛 0，为 0.5 的 E 组归入岛 1，为 0.8 的 D 组归入岛 2。岛 0 当时有两个成员，性能控制器仍要选一个首选 CPU cluster。图 2 从 E 组和 D 组的两次建议出发展示模块之间的传递。

第 1、10、17 项限定先给两个同核型 CPU cluster 设置不同的控制量范围。较高控制量的线程组被放到另一性能岛，先前线程组留在原岛以原控制量继续。在原图 9 的实现中，OS 调度器负责线程放置，可以向性能控制器提供引导跨 cluster 外溢的边权重。

移动成员、热轮转和负载外溢分别改变哪些状态

性能岛是性能控制器管理的对象，可以有零个或多个 CPU cluster。原图 5 的 B、E 组结束后，岛 1 没有活动线程组。控制器可以把原先属于岛 1 的 P-core cluster 2 改归岛 2，并把岛 2 的 C 组推荐到该 CPU cluster。图 4 把归属变化和线程重新放置分开。

原图 6–7 还允许轮换高电压区间对应的 CPU cluster，以分散较高温度和高电压驻留时间。第 9、16 项的边权重作用于线程负载外溢。三类操作作用于不同状态，图表 3 将它们列在一起。收益要以各 cluster 的频率、电压驻留和同一工作总能耗核对，也要观察迁移带来的缓存重热。

轮换高电压性能岛的硬件成员

原图 6 将 P-core cluster 2 作为性能岛 2 的成员，给 C、D 两组运行；P-core cluster 3 在岛 1 服务 B、E 两组。原图 7 保持线程组的性能岛归属，交换岛 1 与岛 2 对应的物理成员。图 5 按物理 CPU cluster 分行追踪轮换前后的电压需求与服务对象。轮换使较高电压驻留时间可以分摊到两个 CPU cluster。

性能控制器改写成员映射，再向 OS 调度器发送新的首选 CPU cluster。说明书允许定时、根据温差，或根据电压与时间加权得到的老化估计触发。是否降低温度峰值取决于轮换周期、散热扩散以及搬迁线程引起的缓存重热。原文未给这些变量的联合数据。
