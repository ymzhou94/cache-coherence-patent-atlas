按性能需求为同类型 CPU 核簇划分性能岛

Performance islands for CPU clusters

两个线程组性能需求差异很大时，能否继续使用同一类型的 CPU 核而分别安排核簇？

工程要点

性能控制器发现第一性能岛没有活动线程组时，可把其 CPU 核簇划给第二岛，再将第二岛的线程组重新布置到该核簇。

成立条件
两岛核簇为同一核类型，控制量范围不同。在此次重分配中，第一岛各核簇都没有已分配的活动线程组。
验证方法
回放相同线程组活跃时间和控制需求，对照固定核簇归属与空岛时重分配。记录重新放置次数、任务开始等待及迁移后的缓存缺失。

工作机制

性能岛是性能控制器管理的一组核簇及其控制量范围。相同核类型的两个核簇可以对应不同范围。

性能控制器依据线程组的控制量（control effort）选择性能岛，并可以通知调度器首选核簇。核簇归属还能随线程组活动变化。

  1. 计算线程组控制量

    性能控制器采样活动线程组，并把控制量与定义好的范围比较。

  2. 选择同类型核簇中的性能岛

    需求较低的组可保留在第一岛，需求更高的组被指向覆盖较高控制量的另一岛。

  3. 通知调度器核簇偏好

    性能控制器更新首选核簇。调度器依据自己的运行条件决定线程实际放置。

  4. 按活动情况调整岛成员

    第一岛没有活动组时，可把其中的核簇转给第二岛，并重新分配线程组。

权项与实施例约束

权 7 允许按照温差重分配同类型核簇，权 8 则使用时间与电压的加权关系。两项都是岛成员策略，可影响随后推荐的核簇，实际放置仍由调度器执行。

工程推演与验证

收益与开销

比较核簇的性能状态驻留时长、温差和跨簇工作集重新预热开销。高低需求组分开可能减少低需求组的高频驻留，也会增加调度迁移次数。

边界场景

维持两组相同工作量和温差阈值，逐步增大共享工作集。若分组后高频驻留下降而 LLC 流量及整机每任务能量上升，跨簇局部性损失可能抵消收益。

条件推演

初始条件
两个活动线程组需要不同控制量，机器有两个同类型 CPU 核簇。
处理结果
较低需求组维持在第一岛，较高需求组被分配到第二岛。第一岛空闲后可重新分配核簇。
结果解读
将线程迁移与运行点变化分开观测。核簇归属和线程首选核簇是两种状态。

关联专利

  • 非对称多处理器的闭环性能控制与热功率约束

    两案都从线程组的控制量形成放置建议。US11579934B2 跨核类型给出核簇和运行点推荐，并处理热功率约束。US12306789B2 将相同核类型的核簇划入控制量范围不同的性能岛，使性能需求不同的线程组可留在同类核上，又不会集中到同一个核簇。

  • 按核簇共享资源饱和度迁移单个线程

    性能岛根据线程组的控制量给出首选核簇。实际运行时，若某一核簇的 BIU 请求队列持续饱和，US12147839B2 用 LSU 微操作指标设置线程标记，允许调度器只迁移相关线程。同组其他线程可以维持原来的核簇放置。
