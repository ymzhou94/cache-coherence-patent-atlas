工作机制

精确目录可以较早处理后续的同址事务。较晚发出的 snoop 若先于回填到达，代理可以把它记在已经等待该块的请求项上。

一致性控制器维护缓存块的持有者和状态。代理收到针对同块的第二条探测时，可以把探测类型等字段写进先前本地请求的缓冲项，等本地请求完成后再处理探测。

  1. 分配本地请求项

    代理 A 请求块 X，在 request buffer 里创建一项，保存本地请求字段。一致性控制器可据此发出第一条探测。

  2. 按块地址确认冲突

    第二条 snoop 抵达 A 时，代理把它的地址与在途请求比较。找到 X 的请求项且符合吸收条件时，就在原项加上探测信息。

  3. 写入探测类型及转发目标

    原缓冲项至少要记下探测类型。适用的转发从属方案还要记第三方目标 ID，前序事务完成后才能按该标识发数据。

  4. 本地请求完成后执行探测

    A 取得前序事务返回的数据或状态后，从同一项读出探测字段。转发类探测可以送出数据块，失效类探测则将该行置为 I。

示例

初始条件
A 读 X，对应缓冲项 R0 还在等回填。这时 A 收到一条要求把 X 转发给 C 的 Fwd 探测。
处理结果
A 在 R0 中记 Fwd 类型和 C 的目标 ID。A 的读完成后，它取得所需状态和数据，再把 X 发给 C。
结果解读
同址匹配和本地请求在途是此例的合并条件。A 先保存供数方向，等有可用数据后再向 C 发送。

工程图解与对照

  • 同一缓冲项保存本地请求和后到探测
  • R0 等待回填时可以接收同址转发探测
  • 完成计数与探测重放共用在途项
  • 请求完成后按探测类型处理

收益与代价

何时有效
同址访问多、且消息可能沿不同通路反序时，代理可用已分配的请求项暂存后到的探测，减少占用独立槽位。
代价和限制
若原项放不下必要字段，或前序请求迟迟未完成，仍可能产生回压。
验证指标
统计吸收比例和各类缓冲项的占用周期。记录同址请求链的完成速率及实际经过互连的消息数。
