GPU 按优先级保留分布式硬件槽，并在检查状态后分配

Software control techniques for graphics hardware that supports logical slots and reservation of graphics hardware based on a priority threshold

核心结论

GPU 用软件提供的优先级给逻辑工作槽筛选可用槽集合。未达到门槛的工作只能映射到通用槽；达到门槛者可以考虑预留槽，还可考虑符合规则的通用槽。分配器随后检查硬件槽状态与分派范围，引导工作由目标 mGPU 的 shader 执行。

优先级如何从软件进入 GPU 硬件槽映射

软件提交 GPU 工作单元（kick）与优先级。工作先进入逻辑工作槽，实际执行位置由 GPU 主控决定。原图 2、6 的分布式槽资源分配器要结合控流请求、硬件槽状态和软件约束。得到目标 dSlot 后，才可以将批次送给相应子单元。

图 1 将指定优先级与资源状态放在同一个分配器的两侧。每个分布式硬件槽（dSlot）有工作队列和对应的配置寄存器。目标 GPU 子单元（mGPU）的 shader 从该槽的工作描述执行。保留的是分布式槽资格，多个槽可以共享这个 mGPU 的 shader 资源。

第 1、11、17 项明确要求未达到优先级门槛的逻辑槽只能映射通用槽。第 9 项分别描述控制流处理器与硬件槽资源分配器。图 1 的工作类型和优先级用 GPU 术语，CPU cluster 与 OS 线程调度另有各自的状态。

工作能提前进入队列，何时能开始执行

依赖、配置就绪、硬件槽资源是不同条件。原图 8 在 kernel 依赖解除且对应 kernel 处理器空闲之后请求槽资源。原图 19A、21 的工作槽管理器可提前预取配置值，也能在部分配置写完前将已分配批次排入目标 dSlot。执行仍要等相关配置写入完成。

图 2 画槽分配请求与已确定槽后的两路动作。主控同时发配置副本和工作描述，而工作队列只在配置通过后开始执行。第 4–6、13–14、19 项覆盖通过软件接口查看等待原因、槽映射和执行时间戳。

预留槽回答资格，分配器另查可用性

原图 13 的预留机制为满足门槛的逻辑槽留专用候选。说明书允许先尝试预留，也允许与通用槽一起参与轮转。表 3 对应候选资格，未指定同等资格时的仲裁细节。

原图 10A–10C 按单 mGPU、单子单元组和多组分别分派，还可能受软件组约束、允许掩码和分派策略影响。槽正在运行、清缓存或保留时，需要按相应规则处理。优先级满足并不能证明任何时刻都能发批次。

低优先级占满通用槽时，哪条分配路径仍存在

图 4 设一个 mGPU 提供三个 dSlot。两个通用槽已经被低优先级工作占用，一个满足门槛的预留槽仍可分配。若有高低两个新请求，低优先级继续等待可用通用槽，高优先级可得到预留槽。

该示例隔离槽分配作用。已经占用槽的任务与新任务可能共享 shader，依赖和上下文配置也会造成额外等待。若要测入队到首个工作组开始执行的收益，应同时记录已有槽占用、配置写入耗时和实际执行资源利用率。

通用资源短缺时，怎样回收已排空的低优先级槽

原图 11A、11B 说明槽回收与预留是两个决策。资源分配器先看已经在执行缓存清理的槽是否足够。数量不足才看已排空、有明确所有者、该所有者未在保存上下文且没有其他槽正在清理的候选。

图 5 展开回收条目选择。保留意向低通常说明该旧工作不会再请求槽；更高保留意向按优先级及任务年龄进一步筛选。满足所需槽数量时，回收方发缓存清理及失效操作；回收槽完成清理并成为无所有者状态后，分配器可以再次仲裁。第 10、16 项覆盖更高优先级逻辑槽回收已分给低优先级工作的 dSlot。

结束后保留硬件槽，怎样交还资源

原图 12 的显式保留为软件采集性能状态等用途。工作已执行完，系统可以完成 kernel 尾部缓存清理，并报告这次工作完成，但保持 dSlot 映射。这个状态可阻止其他逻辑槽回收这些 dSlot。

图 6 显示软件查询结束后通知释放。主控解除映射，原所有者的分布式槽进入可重新分配状态。第 2、12、18 项要求在软件释放指示后，才把已保留的槽映射给另一逻辑槽。保留没有改变预留槽的优先级门槛。
