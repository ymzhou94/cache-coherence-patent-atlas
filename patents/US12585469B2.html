预测 trace cache 缺失时关数据读，保留标签查询

前端还没有拿到实际命中结果，能否少读一次 trace 指令数据阵列？如果关读之后标签却命中，处理器会用什么供给指令，又怎么纠正预测？

取指前端预测 trace 缺失时关闭对应数据阵列的读取，同时保持 trace 标签查询和普通 I-cache 取指。实际标签结果与读预测不一致时可训练预测器。本次关读仍然生效。已预取到缓冲且符合使用条件的 trace 还有独立供给路径。

关掉的数据阵列与仍在查的标签

普通 I-cache 保存顺序地址中的指令。trace cache 把预测控制流上的指令放在一起，某些 trace 跨越内部 taken 分支。前端若对每个取指地址都同时读两套指令数据，即使 trace 没命中，也会产生数据阵列活动。

沿图 1 从取指组地址看三条路径。普通 I-cache 照常接到取指请求。trace 标签阵列照常查实际命中。早到的读使能只控制 trace 指令数据阵列。在本次预测缺失时，时钟门控或其他门控机制可以阻止该阵列的读取。

预测缺失后碰到真实标签命中

图 2 用一次误关读说明时机。前端按预测关闭 trace 数据读，同时启动普通取指和 trace 标签查询。随后标签结果表明这笔访问本来可以命中。标签提供训练所需的事实，指令数据仍由本例命中的普通 I-cache 提供。若普通 I-cache 也缺失，通常还要等它回填。

只要不抑制标签查询，预测器就既能发现误开读，也能发现误关读。权利要求 1 不要求这次实际标签命中后重新开启数据读。权利要求 8 则把对照真实标签结果来训练写入从属限定。

预测字段分别跟随顺序地址、跳转目标和返回目标

图 3 上路为顺序取指。用取指组虚拟地址的部分位或散列标记预测项，命中后读出对应预测字段。字段可用饱和计数器，替换信息用于选择逐出的预测项。

中路与下路的预测结果随预测目标返回。Next Fetch Predictor 可以同时给下次取指地址和该目标的 trace 读使能，覆盖普通控制流跳转和 trace 到 trace 的转移。返回预测器也可以按返回指令的 PC 查预测目标与读使能。说明书给出返回预测表未命中时默认开读的实施例。

需求阵列关读以后，预取缓冲是否还能供给

图 4 上路是另一项预测。签名 lookahead 预取电路可以提前从 L2 trace cache 取数据，装进 fast array。预取缓冲在常规 trace 数据阵列降低功耗时仍可保持供电。在有对应条目、且匹配这次前端访问的实施例中，预取路径可继续供给。

表 5 把数据读使能与真实标签结果逐项对应。误开读主要增加未被采用的数据阵列访问。误关读可能失去 trace 的一次供给机会。若普通取指仍可提供足够指令，丢掉这次 trace 供给的影响可能很小。

预测器追不上执行阶段变化时的代价

表 6 保持相同取指地址和访问次数，只改变它的真实标签结果序列或计数器初值。先命中再缺失的阶段切换会留下短暂的误开与误关。标签命中和缺失交替时，初值能改变整个窗口的关读比例。这里用简单的两位计数器复现这种滞后，专利还披露其他预测算法。

要测能效，至少比较普通指令供给、trace 数据读次数和额外预测访问能量。标签仍然查询，不能把省掉的数据读等同于整个 trace cache 的能量下降。若每次预测有额外成本，只有省掉的数据读能量超过这部分成本，模型中的阵列收益才会转化为净收益。

哪些是独立权利要求，哪些是实现细节

独立权利要求 1、11 给出预测缺失时查 trace 标签、读普通 I-cache、保持 trace 数据读关闭的组合，权利要求 18 描述相应硬件设计表示。三个预测来源的字段见权利要求 2–6、12–14。实际标签反馈、预取缓冲与低功耗状态是进一步描述的部件与路径。
