工程要点

前端预测轨迹缓存缺失时关闭 trace 数据阵列，保留标签查询并读取普通指令缓存。

成立条件
即使标签后来匹配，同一次访问仍保持 trace 读关闭。前端可用实际标签结果反馈读预测器。
验证方法
固定取指序列和标签结果，对照始终读取 trace 数据阵列与按预测使能。按预测和实际命中组合记录两类数据阵列读次数、供给指令数和再次取指次数。

工作机制

trace cache 用标签判断轨迹是否存在，由独立的数据阵列提供轨迹中的指令。单独访问标签，可以在关闭数据阵列时保留训练所需的实际命中结果。

预测轨迹缓存缺失时，前端仍查询轨迹标签，同时从普通指令缓存请求数据，轨迹数据阵列保持关闭。即便标签后来命中，也不恢复本次轨迹数据读。普通指令缓存若缺失，仍须等回填。

  1. 把取指地址送给各路径

    前端把 fetch group 地址送给 I-cache、trace 结构和读预测器。顺序取指、非顺序目标和返回路径可提供不同预测信息。

  2. 用预测控制数据阵列读使能

    读预测器给出命中或缺失的预测。预测缺失时关闭 trace 数据读使能，并从 I-cache 取指令。

  3. 保留标签查询

    标签电路继续检查该地址是否有相应 trace。独立权利要求规定，实际标签匹配也不会让同一次访问重新启动 trace 数据读。

  4. 用实际标签结果训练

    预测器将实际标签结果与先前判断比较并训练。部分从属结构还可支持从远层提前取轨迹，由另一条功能路径完成。

权项与实施例约束

权 2 让下一取指预测器的条目包含读取使能字段。权 3、4 还描述单独的顺序预测阵列，可在分配轨迹缓存条目时为顺序路径建立对应预测。

收益与开销

预测关闭时，标签阵列仍要做地址匹配，也要保留训练所需反馈。能耗变化主要发生在轨迹数据阵列和额外取指次数，单数关闭数据读不能代表前端整体节能。

边界场景

若一段代码频繁在顺序落入和分支跳入同一取指地址之间切换，两套来源可给出不同读预测。若常见的跳入路径多次误报缺失，I-cache 会重走跨分支取指。

条件推演

初始条件
假定取指块 X 被预测为 trace 缺失。I-cache 返回顺序指令，trace 标签随后也匹配到了 X。
处理结果
前端在这次访问中使用已启动的 I-cache 读取。实际的 trace 匹配结果可用于训练之后的预测。
结果解读
独立权利要求覆盖这种预测与标签不符的情况。此时前端仍能从 I-cache 取得顺序指令。

专利原文

关联专利

  • 用客户端状态约束共享内存的门控深度

    轨迹缓存预测缺失时关闭本次数据阵列读取，同时查标签并访问指令缓存。即使标签意外命中，本次数据读取仍保持关闭。另一专利用异构客户端的运行参数限制共享内存资源的时钟或电源门控，权 7 取各客户端阈值中最活跃的状态。两处的控制范围分别是单次取指和共享资源的电源状态。

  • 支持多种长度的分层 trace cache

    US18/627,035 与 US18/627,001 在各自说明书记载的关联申请中互相引用。前者权 1 在预测缺失时抑制本次数据阵列读取，后者权 1 用预取缓冲区向取指前端提供来自二级轨迹缓存的长轨迹。
