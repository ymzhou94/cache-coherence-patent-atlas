预测 trace cache 未命中时关闭数据读

Trace cache access prediction and read enable

前端预测 trace cache 会缺失时，为什么还要读标签？

工作机制

trace cache 用标签判断轨迹是否存在，由独立的数据阵列提供轨迹中的指令。单独访问标签，可以在关闭数据阵列时保留训练所需的实际命中结果。

读取预测器判断取指地址是否会命中轨迹缓存。预测缺失时，前端仍查询该缓存的标签，同时启动指令缓存读取，轨迹数据阵列保持关闭。即使随后确认轨迹缓存命中，本次取指仍沿已启动的指令缓存路径完成。

  1. 把取指地址送给各路径

    前端把 fetch group 地址送给 I-cache、trace 结构和读预测器。顺序取指、非顺序目标和返回路径可提供不同预测信息。

  2. 用预测控制数据阵列读使能

    读预测器给出命中或缺失的预测。预测缺失时关闭 trace 数据读使能，并从 I-cache 取指令。

  3. 保留标签查询

    标签电路继续检查该地址是否有相应 trace。独立权利要求规定，实际标签匹配也不会让同一次访问重新启动 trace 数据读。

  4. 用实际标签结果训练

    预测器将实际标签结果与先前判断比较并训练。部分从属结构还可支持从远层提前取轨迹，由另一条功能路径完成。

示例

初始条件
假定取指块 X 被预测为 trace 缺失。I-cache 返回顺序指令，trace 标签随后也匹配到了 X。
处理结果
前端在这次访问中使用已启动的 I-cache 读取。实际的 trace 匹配结果可用于训练之后的预测。
结果解读
独立权利要求覆盖这种预测与标签不符的情况。此时前端仍能从 I-cache 取得顺序指令。

收益与代价

何时有效
很多取指地址不会命中 trace 时，准确预测缺失可以减少不必要的阵列读取。
代价和限制
如果预测器频繁误报缺失，前端会错过本可供给的跨分支指令。额外取指增多时，净收益会缩小。
验证指标
把预测 hit 或 miss 与实际 hit 或 miss 交叉成四种情况，分别统计数据阵列读取、供给指令数和额外取指。

权利要求与出处

独立权利要求为第 1、11、18 项。下方列出部分权利要求的中文释义。

权 1
预测 trace 缺失时，查询 trace 标签并读 I-cache，关闭 trace 指令数据读取。实际标签匹配时仍维持这次读取决定。
权 8
用实际的标签比较结果与读预测对照，训练预测器。
