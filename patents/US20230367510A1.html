可编程地址 hash 决定页内块经哪条互连到哪个内存控制器

Address Hashing in a Multiple Memory Controller System

一个物理页的相邻块怎样被映射到多个内存控制器？控制器内部省去部分物理地址位之后，怎样在需要时重建原地址？

核心结论

互连按可编程 mask 对同一物理地址的多个子集做 hash，结果定位 die、slice、row 和 side。目标控制器可继续选择 plane、pipe 等，并在内部缓冲只存压缩地址。需要完整地址时，从已知路由结果和保留位反推出省略位。

同一个物理地址并行输入多个层级的 hash

图 1 左侧是一条请求的物理地址和一组内存位置配置寄存器（MLC）。配置为每层选择参与 hash 的地址位，并可反转结果。示例对各层的选中位做 XOR reduction，得到 die、slice、row、side 的选择结果。原图 3 虽以树形列出层级，说明书 ¶0043 允许各选择并行求值。

用 die 字段作例子，mask 全零时 XOR 输出 0。若该层的反转位也为 0，所有相关地址的这一维都选择 0；反转位置 1 后，这一维固定为 1。不同层可以采用不同 mask。公开第 35 和 36 项分别限定地址位选择和结果反转。

互连送达目标控制器，控制器可继续选择本地通道

沿图 2 的请求方向追踪。互连得到目标位置后，把请求传到相应内存控制器。控制器随后可以用 plane、pipe、bank group 和 bank 的配置继续选择其内部资源或所连 DRAM。本文的 row 指控制器物理布局在一个 slice 内的排布，DRAM row 是内存阵列行。

表 3 并排给出各层的输入、输出和可执行部件。说明书 ¶0051 允许具有不同 MLC 字段的硬件代理。部分代理只算到内存控制器，有的可提前选择 plane 或 pipe。OS 页表给出物理地址，互连 hash 使用这个地址进行路由。

相邻页块的落点按真实 die 和互连段对照

图 5 将原图 2 示例的前四个块按目标 die 和 side 摆放。按偏移读，块 0 到 die 0 的西侧控制器 A，块 1 到 die 1 的东侧控制器 G，块 2 到 die 1 的西侧控制器 D，块 3 到 die 0 的东侧控制器 F。顺序访问因此能在短时间内抵达几个物理位置不同的控制器。

不同目标可分摊控制器请求和部分互连段的流量。完整路径是否重合，还取决于发起代理及具体互连。公开第 29 和 40 项限定两条完整路径不重叠；主权项所述页内分散本身没有要求所有路径都物理独立。

压缩地址利用已知 hash 结果恢复省略的位

图 4 用可复算的两级 XOR 例子说明可逆性。设 die 结果 D = a XOR c XOR 1，slice 结果 S = b XOR c。由于 a 只出现在 die hash、b 只出现在 slice hash，控制器用落点对应的 D、S 和保留的 c 就能分别解出 a、b，再插回原位置。内部缓冲只记 c、d。

枚举四位输入的 16 种组合，检查压缩的 c、d 与选定的 D、S 是否唯一决定原输入，全部可逆。比如输入 a、b、c、d = 1、0、1、1 时，D、S = 1、1，代回分别得到 a = 1、b = 0。多个地址位可跨层共享。为了在该示例中独立恢复，实际省去的位在各自 hash 中是唯一的。

公开第 34 项限定恢复参与 hash 的地址位。说明书进一步披露内部缓冲使用 compacted pipe address，必要时例如生成带完整地址的 snoop 时再恢复。影响面积和功耗的是每项内部保存的位数及读写活动，同时要计入恢复逻辑。

页内分布、恢复以及低功耗折叠对应不同技术条件

按这份 A1 公开文本，第 1–25 项已取消，本文以公开第 26、38、43 项和对应从属项分析。三项都写到页内块分布、互连对规定地址位执行多层 hash，以及配置寄存器的粒度字段。原图 8–11 另披露监控访问率、迁移活跃页与停用 slice 的折叠机制。

在手机 SoC 中验证地址映射的实际效果，需要按内存控制器分别计数，观察同一请求流在互连段的重叠，以及行局部性、跨 die 链路负载和延迟变化。跨控制器地址分布是本专利的机制，图中的布局与寄存器例子属于说明书实施方式。
