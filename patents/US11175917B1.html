工程要点

重放缓冲记录相依 load 与 store 的标识，在保留站发射该 store 的数据操作时触发 load 重执行。

成立条件
首次执行已有 store queue 地址命中，所需 store 数据尚未写入，且重放缓冲能分配表项。
验证方法
用同一笔 store 数据操作和同一 load 端口排程，对照发射时触发与写入 store queue 后触发。记录 load 重发拍和首次能实际转发数据的拍。

工作机制

store 的地址和数据由不同操作产生。load 查到应读的旧 store 时，该 store 的数据可能还未写入队列。

load 首次查到旧 store 但数据未到时，LSU 触发重放。并列于保留站的重放缓冲记录两项操作的标识，监听保留站发射对应的 store 数据操作，并尝试提前重发该 load。

  1. 记录阻塞 load 的 store

    第一次执行时若地址匹配、所需数据还没到，load 必须重放。重放缓冲用这条 load 与阻塞它的 store 的标识定位依赖。

  2. 在两张表保留重放所需信息

    RLB 表项保存匹配所需的 store 标识和 load 标识，也可带目标寄存器等字段。普通 load 执行队列保存其余字段，在重新发射时补齐。

  3. 用数据操作发射作为触发点

    保留站发射 store 数据操作时，缓冲用它的序号找出关联的 load，并可向 load 流水线提前发出重执行请求。

  4. 未能提前调度时走普通路径

    没有分到 RLB 表项时，load 留在 LEQ，等普通路径检测到相应 store 数据后重新发射。原图 3 的 LEQ 在 store 数据操作的 DT 阶段取得 SNUM，并经过重放仲裁。若 RLB 已经成功安排发射，LEQ 标记该 load，避免重复重发。

权项与实施例约束

权 2 允许保留站在首次发射后删除原 load。权 3、4 把重执行所需字段分在重放缓冲和 load 队列，重新执行时由后者把剩余字段送入流水线。

文中术语
RLB
Replayed Load Buffer。保存因 store 缺数据而要重发的 load 信息。
LEQ
Load Execution Queue。保存 load 的执行状态并提供常规重发路径。
SNUM
store 操作的序号，用来把该 store 的数据操作与等待它的 load 配对。

收益与开销

快唤醒的直接输入是 store 数据操作的发射标识。一条 load 的地址、控制和队列状态仍需在重执行时归并。节省的等待要扣除字段汇合及 load 端口仲裁。

边界场景

若一笔 store 的数据操作恰好唤醒多条匹配的 load，各项会同时竞争有限的重发端口。即使检测提前，排在后面的 load 也可能已经错过能节省的窗口。

初始条件

处理结果
快速路径在 store 数据操作发射时匹配标识。图中的 L 比普通路径早 4 个周期发射并收到转发数据。
结果解读
4 个周期来自该说明书时序。比较两条路径时使用相同的 store 发射拍、依赖关系和转发端口调度。
