并行重放缓冲加快等待 store 数据的 load

load 的地址已匹配到旧 store，数据还没到，何时可以重发？

工程要点

重放缓冲记录相依 load 与 store 的标识，在保留站发射该 store 的数据操作时触发 load 重执行。

成立条件
首次执行已有 store queue 地址命中，所需 store 数据尚未写入，且重放缓冲能分配表项。
验证方法
用同一笔 store 数据操作和同一 load 端口排程，对照发射时触发与写入 store queue 后触发。记录 load 重发拍和首次能实际转发数据的拍。

工作机制

store 的地址和数据由不同操作产生。load 查到应读的旧 store 时，该 store 的数据可能还未写入队列。

load 命中 store queue 但所需数据未到时，重放缓冲记录两项操作的标识。它与保留站并行工作。保留站发射对应的 store 数据操作时，缓冲可据此触发 load 重执行。

  1. 记录阻塞 load 的 store

    第一次执行时若地址匹配、所需数据还没到，load 必须重放。重放缓冲用这条 load 与阻塞它的 store 的标识定位依赖。

  2. 把其余字段留在 load 队列

    快速匹配只需要一对标识。普通 load 队列可以继续保存完整执行需要的其余状态。

  3. 用数据操作发射作为触发点

    保留站发射 store 数据操作时，缓冲用它的序号找出关联的 load，并可向 load 流水线提前发出重执行请求。

  4. 未分到缓冲项时走普通路径

    若缓冲已满等原因导致这条 load 未分配快速重放项，普通 load 队列等 store 数据写入 store queue 后再调度。两条路径需要转发同一个较新的值。

图解与对照

  • 第一次查到 store 时还取不到数据
  • 重放缓冲从保留站等来发射标识
  • 说明书示例中，重放缓冲使 load 早发 4 拍
  • 快速和普通重放等待不同事件

实验与取舍

何时有效
load 已经知道依赖哪条 store、只差数据时，提前调度可以减少串行等待。
代价和限制
缓冲已满、发射口繁忙，或提前唤醒的 load 与可转发数据错开时，收益会缩小。
验证指标
在同一事件序列中记录地址首次匹配、store 数据操作发射、load 重发和数据转发的时刻，再算缓冲满的比例。

教学算例

初始条件
沿用图 3、4 的时序。load L 首次命中 store S 的地址，但缺数据。分别让 L 使用重放缓冲和普通队列。
处理结果
快速路径在 store 数据操作发射时匹配标识。图中的 L 比普通路径早 4 个周期发射并收到转发数据。
结果解读
4 个周期来自该说明书时序。比较两条路径时使用相同的 store 发射拍、依赖关系和转发端口调度。
