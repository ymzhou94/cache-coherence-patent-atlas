基于 I/O 吞吐量的 CPU 闭环性能控制

Closed loop CPU performance control

内存控制器观测的 I/O 吞吐量，能提供哪些 CPU 利用率缺少的信息？

工程要点

控制器读取内存控制器的吞吐量并识别工作类型。两条吞吐偏差分别与各自历史值积分，形成调节 CPU 性能状态的控制信号。

成立条件
实施例分别采样内存控制器与 CPU 之间、与闪存子系统之间的流量。若下游已饱和，升高 CPU 性能状态未必能提高相关路径的吞吐量。
验证方法
固定采样周期和负载，比较固定 CPU 性能状态和按吞吐反馈调节。分别统计两路稳态吞吐、达到目标所需时间、状态切换次数和每单位传输量的能耗。

工作机制

CPU 利用率描述执行资源的占用，内存控制器的方向吞吐率描述实际完成的数据传输。专利说明书给出多个反馈量，授权权利要求 1、8、14 聚焦吞吐采样和两个独立积分状态。

控制器在内存控制器采样吞吐率，据此识别进程和工作负载类型。各方向的偏差分别进入各自的积分器，形成控制 CPU 运行模式的信号。比较并采用较大控制信号是权利要求 6、7 的新增限定。

  1. 设置观察点

    内存控制器统计 CPU 与闪存子系统往返的数据流。测量点给出单位时间内的数据量。调度器记录的 CPU 利用率对应执行时间占比。

  2. 识别任务并计算差值

    监控逻辑根据吞吐辨识进程和约束的工作类型。图 5A 的示例给不同方向设阈值，分别输出偏差。

  3. 分别累积各路吞吐量误差

    第一路与第二路分别累积自己的历史差值。说明书也列出四路实现，把 CPU IN／OUT 和闪存 IN／OUT 分开。

  4. 选择控制并作用于 CPU

    电源管理器按输出调节工作模式。从属权 6、7 用反馈较大的路径控制。新的 CPU 性能状态可能改变处理速率与 I/O 吞吐量。

收益与开销

把吞吐变化拆成 CPU 产生或消费请求的速率与存储路径服务速率。两者可用队列占用、各方向字节数/秒和 CPU 每字节能耗区分。

边界场景

限制闪存端的稳态服务速率，再保持数据量不变扫描 CPU 运行点。若内存控制器队列始终满且吞吐不变，CPU 提速所得数据率无法覆盖其新增能耗。

条件推演

初始条件
两路旧积分为 2 和 1，当前偏差增量为 1 和 4。教学规则直接求和并取大。
处理结果
第一路更新到 3，第二路更新到 5，由第二路决定教学控制量。即便第一路旧积分更大，新一轮也可能切换主导通道。
结果解读
积分类控制跨窗保存状态。示例没有建模增益、饱和或抗积分饱和，也不把 5 映射成某个实际档位。
