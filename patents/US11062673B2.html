工作机制

这是 2012 年优先权的历史闭环系列代表，授权公开于 2021 年 7 月。说明书将 CPU 指令类型、GPU 利用率、图形帧率和存储流量分作不同观测。此处按授权权项聚焦存储流量和双积分。

采样内存控制器处的各方向吞吐，识别运行工作并计算偏差。各条反馈分开积分，再据控制信号调整 CPU 工作模式。较大反馈优先是从属权利要求中的一种选择方式。

  1. 设置观察点

    内存控制器统计 CPU 与闪存子系统往返的数据流。该点看到的是通过量，和调度器记录的 CPU 忙时不同。

  2. 识别任务并计算差值

    监控逻辑根据吞吐辨识进程和约束的工作类型。图 5A 的示例给不同方向设阈值，分别输出偏差。

  3. 把历史留在各自反馈路

    第一路与第二路分别累积自己的历史差值。说明书也列出四路实现，把 CPU IN／OUT 和闪存 IN／OUT 分开。

  4. 选择控制并作用于 CPU

    电源管理器按输出调节工作模式。从属权 6、7 用反馈较大的路径控制。新的档位随后改变处理和供数速率。

示例

初始条件
两路旧积分为 2 和 1，当前偏差增量为 1 和 4。教学规则直接求和并取大。
处理结果
第一路更新到 3，第二路更新到 5，由第二路决定教学控制量。即便第一路旧积分更大，新一轮也可能切换主导通道。
结果解读
积分类控制跨窗保存状态。示例没有建模增益、饱和或抗积分饱和，也不把 5 映射成某个实际档位。

工程图解与对照

  • 采样存储吞吐并保留独立积分状态
  • 一次采样到下一次观测
  • 相同采样窗内的双积分反馈
  • 单次更新如何更换主导通道

收益与代价

何时有效
工作受可通过 CPU 提速改善的供数瓶颈限制时，吞吐反馈可弥补利用率单一观察的不足。
代价和限制
若下游本身已经饱和，CPU 提速可能只拉高功耗。观测延迟和积分增益过大还会增加往返调档。
验证指标
用同一工作负载比较固定档和反馈档，统计吞吐、目标偏差、功耗、调档频率和控制稳定时间。
