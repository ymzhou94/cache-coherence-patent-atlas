CPU 闭环调频如何使用内存控制器吞吐量

哪些访存流量值得给 CPU 更高的运行点，多条反馈同时提出请求时怎样取舍？

内存控制器分别采样 CPU 和闪存的入向、出向吞吐量。监视器独立比较各路阈值并积累吞吐量偏差，按原图 5A 可采用最大的控制量。功率管理器依据选中值更新 CPU 的运行点。原图 6 的界面帧率条件作用于另一组 CPU 利用率反馈。

四路吞吐量各有阈值与积分状态

原图 5A 将吞吐量按两个端点、两个方向采样。监视器将每一路与自己的阈值比较，根据吞吐量偏差更新本路积分状态。闪存活动也可以参与 CPU 运行点选择，例如闪存设备驱动的 CPU 执行速度影响端到端读写。

图 1 将内存控制器的采样点与 CPU 的执行点分开。调高 CPU 运行点能改善 CPU 发起事务或处理数据的速度，前提是性能瓶颈确实在 CPU。若 DRAM 接口已饱和或延迟受其他主设备争用主导，单凭高吞吐量无法判断升频收益。

比较的是积累后的控制量

图 2 中，原图 5B 的采样、偏差计算、独立积分和取大依次结束，再把控制量映射为 CPU 电压、频率或其他处理器运行配置。独立权利要求第 1、8、14 项写明至少两路吞吐量偏差按各自历史积分，取大见第 6、12、17 项，按较大值调整见第 7、13 项。

图表 3 采用同一无量纲控制量刻度，展示一次更新后最大值如何由 CPU 方向切换到闪存方向。说明书描述的一个实现将控制量表示为 0–255，可以线性映射至合格的频率或电压。表中的数既没有量化吞吐量，也没有指定实际 DVFS 运行点。

另一个实施例怎样抑制按 CPU 利用率升频

原图 6A 中，一路统计采样窗内至少一颗核心活跃的时间占比，另一路对各核心活跃时间求和并按核心数量和窗口长度归一。两路分别比较目标值并积分，取大后由界面帧率门控。图 4 将门控前的控制源和门控后的运行请求放在同一图中。

界面活动满足门槛时，原图 6A 将这一对利用率控制的输出置零，原图 6B 对应终止该次调整。这样可以避免仅因界面密集任务的 CPU 忙等而升频。独立权利要求保护的吞吐量路径与这个界面门控是不同实施路径。

帧率反馈如何区分相邻帧抖动和长期变化

原图 2A 以帧缓冲更新时刻为输入。短环使用连续三次更新的两个帧间隔，分别取倒数得到瞬时帧率，取二者差的绝对值。长环使用间隔较长的两次帧率样本。两个变化量有各自的阈值和积分状态，原文的示例阈值分别为 3 FPS 和 1 FPS。

动画即使长期平稳，帧定时不精确也会给出较大的相邻样本差。原文允许在长环控制量低于很小的 ε 时给短环的偏差比较输入 0，负偏差使短环控制量下降。若距上次帧缓冲更新已超过设定时限，可清除两路积分。图 5 展示这条帧率控制路径。图 4 中的帧率门槛决定另一条 CPU 利用率反馈是否递交请求。
