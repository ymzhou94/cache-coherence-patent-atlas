子队列如何利用数据总线忙时的命令周期

Arbitration sub-queues for a memory circuit

写请求还有数据未发完。命令总线此时空闲时，为什么另一个请求可以先发，什么情况下还是被挡住？

核心结论

队列管理器按地址把请求分散到多个 FIFO。仲裁器从各队首检查下一周期是否能承载请求。数据总线忙时，无需发出数据操作数的合资格队首仍可使用命令总线。

地址分队与总线发出是两个决定

图 1 中每个请求源都有队列管理器，按地址范围或散列结果选子队列。申请同一个存储系统的请求可先在多个 FIFO 中等待。总线仲裁器看到各队首，同时检查命令总线与数据总线的用量。

这里的「只带命令」指在这个出站方向没有要随请求发送的数据操作数。读请求仍会有返回数据。数据总线忙且命令总线可用时，它可以发出不含出站数据操作数的命令。这条规则依赖分开的命令总线和数据总线。

W0 的尾段怎样与 C 的命令同时传输

图 2 从原图 2 抽出三笔请求。W0 首个周期发送地址和第一段数据，周期 1 继续发送尾段。W1 虽处在另一队首，但需要发出数据，暂时无法使用总线。C 只发命令，便可填这一周期的命令位置。

下一周期数据总线释放后，从更新的队首集合中选择请求。例中 W1 当时发出命令和第一段数据。它的剩余数据继续占用后续周期。表 3 列出这三笔访问的资格条件。原图中的请求组合和其它仲裁规则可能改变排程。

命令 C 和 W1 被散列到同一 FIFO 时仍会阻塞

图 4 对照同样的输入。若 C 排在 W1 后面，数据总线仍忙的周期 1 无法把 W1 从队首发出，C 又未成为候选。另一种布局中 C 属于独立 FIFO，能单独通过资格判定。这个对照说明地址分布如何影响队首阻塞。

以 W0 两段数据、W1 三段数据、C 不带数据的每周期模型核对，分队时 C 在周期 1 发出，合队时周期 3 才发出。两种布局里的 W1 都在周期 2 发出，整批数据尾段都在周期 4。该例可以缩短 C 的等待和命令总线空闲时间，整批写入结束时刻仍受数据尾段限制。

资格通过之后才比较 credit 或最近授权

图 5 把两次选择分开。先从各队首排除当前不能发的请求，并根据实现检查请求源的 credit。之后可从合资格队列里选最久没有拿到总线的一个。胜出队列的计数重置，其他队列计数更新以供下一轮比较。

专利还描述按队首 credit 提高请求源优先级、计数器集中或分布等选项。即使等待很久，只要 W1 所需的数据总线在下一周期不可用，它仍留在原 FIFO。性能测量需要看队首阻塞比例、命令／数据总线利用率和各类请求调度等待。
