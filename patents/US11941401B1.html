返回地址预测附带后续取指宽度和 bank

Instruction fetch using a return prediction circuit

RAS 只预测 RET 返回到哪条指令时，前端如何同时知道返回之后读多宽、访问方向预测器的哪一个 bank？

  • 核心结论
  • 同一个 RET 可对应多个续段，参数随返回地址选择
  • 先实测续段布局，再在 call 或 return 取参数
  • 错误提示不会改变需要验证的返回地址
  • 预测表容量与调用结构决定训练的复用率

核心结论

用 RAS 的返回地址访问一份单独的续段参数表。首次返回学习宽度和方向预测 bank，之后在 call 侧将参数一并压栈，或在 return 侧据已取出的地址查表，合成带提示的请求。

同一个 RET 可对应多个续段，参数随返回地址选择

原图 1–4 把返回预测元数据用于 CPU 内部的指令取数和分支方向预测。原图 10 给出装有 CPU 的 SoC 及手机用途。

同一子程序可被不同 call site 调用，RET 的地址相同，后继不同。RAS 通过调用关系解析地址。按这个返回地址找到宽度和 bank 后，前端把宽度带给 I-cache，把 bank 和地址带给方向预测器。

先实测续段布局，再在 call 或 return 取参数

首次 call 的参数表未命中时仍记录返回地址。等对应 return 后，用正常取回的续段和方向预测查询结果生成一项。已有项时，原图 1 的两种实现分别把查表安排在 call 或 return；call 端查表可减少 return 上的串行访问，但栈要增加元数据字段。方法独权 10 明确要求前一种 push/pop 参数方式。

错误提示不会改变需要验证的返回地址

原图 3 的宽度如果停在后续控制转移之前，前端可以取回全宽组后重算。方向预测器错开 bank 时可用其他 bank 的查找结果反馈。最终应分别测量窄读减少的字节数、少激活的 bank 和恢复额外请求。

预测表容量与调用结构决定训练的复用率

原图 4、7 给出从 LFSR 选择入口位置开始扫描的例子。相应位置没有可用槽时调节条目计数，达到阈值才覆盖。这样定期反复返回的地址更可能命中已有参数。母案独权围绕返回地址训练和消费，继续申请 US12430134B2 的独权指向顺序取指地址及其元数据。
