工程要点

一致性点在 copy-back 请求中携带旁路指示，引导携数据的响应在互连中转给原读代理。

成立条件
请求指示决定代理数据的转发路径，控制器跟踪原响应的完成时点需单独观察。
验证方法
固定远端修改副本和互连负载，比较同类请求的旁路指示开关。分别记录读代理收数与内存控制器收响应的时间。

工作机制

这件专利规定旁路由内存控制器决定。控制器随 copy-back 请求把决定传给持有修改副本的代理。

内存控制器发现另一代理持有目标数据的修改副本，就在发给它的 copy-back 请求里加入旁路指示。供数代理返回数据时，互连可按这项指示把数据转给原请求者。原响应也可继续送控制器，以便完成一致性记录。

  1. 找到持有修改副本的代理

    内存控制器收到读请求后查一致性记录，确认另一代理持有目标数据的修改副本。

  2. 将旁路指示随请求发出

    一致性点把旁路指示放进发给供数代理的 copy-back 请求。指示可表明是否旁路，也可带有定位目标簇的信息。

  3. 按响应信息向原请求者回填

    供数代理返回修改数据。互连根据响应携带的关联信息将数据旁路给原请求者。某个实施例由汇聚节点构造回填。

  4. 把原响应另送控制器

    给请求者的数据和给控制器的原响应可以并行发送。控制器仍可完成原事务的记录，并抑制重复回填。

权项与实施例约束

权利要求 5 要求旁路指示携带接收代理标识，生成的 fill 沿用该标识。权利要求 2、3 则保留送往内存控制器的原响应，并由控制器避免再发重复 fill。

文中术语
复制返回请求（CpBkRq）
一致性点向持有副本的代理发出的供数请求，本件可在其中携带旁路指示。
读发起簇 ID
原读请求方的簇标识。有效时可由持有簇复制到响应，供节点选择下行回填队列。
MO TT 信用
内存控制器中可用事务表表项的流量控制单位。说明书给出为旁路请求预留表项的实施例。

图解与对照

  • 节点可以同时送出旁路回填和原响应
  • 内存控制器在回送请求里指定旁路
  • 生成旁路请求时可提前取得事务表信用
  • 同样是修改副本，返回路径由请求指示决定

收益与开销

请求代理早收数与控制器获得一致性处理所需响应可以并行。原响应仍占用上行通路，收益应从目标收到的数据时间衡量，同时记录两条路径的消息数。

边界场景

若互连接收两路输出的资源共享且饱和，保留原响应可能让上行拥塞持续存在。仅打开旁路标志不足以推断整网流量同步下降，须按收到的消息种类分计。

模型算例

初始条件
A、C 各有一笔读需要 B 的数据。作为分支示例，控制器在 A 的 copy-back 请求中指定旁路，在 C 的请求中采用常规返回。
处理结果
B 发出的两笔响应都携带数据。互连识别请求的指示后，给 A 提前回填，让 C 的响应继续上行，由控制器处理。
结果解读
A 和 C 代表两笔独立事务。旁路指示随每笔请求发送，实际路径取决于该笔事务满足的条件。

  • 汇聚节点把复制返回响应转成跨簇回填

    两件同族专利分别描述回填旁路的指示和执行。US11537538B2 权 1 由一致性点在 copy-back 请求中携带旁路指示，持有修改副本的代理据此返回响应。US11016913B1 权 1 由互连汇聚节点把该响应转换为直达读请求者的回填。两件各自的权 2 另规定原响应也送往内存控制器。
