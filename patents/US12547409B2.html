支持多种长度的分层 trace cache

Trace cache that supports multiple different trace lengths

较远的 trace cache 怎样在前端需要之前送来长指令路径？

工作机制

遇到已预测为跳转的分支，接着执行的指令可能跨越连续地址范围。trace 按执行路径组织指令，可以把转移前后的指令放在同一条路径中。

trace cache 分层保存包含内部已跳转分支的指令路径。较远层能存更长的 trace。控制器预测某条 trace 将执行时，可先从远层读出，把它放进支持该长度的预取缓冲供前端取用。

  1. 识别可构建的路径

    I-cache 按连续地址保存指令。前端按 trace 的构建条件识别执行路径，这里的 trace 包含内部 taken 分支。

  2. 把长项放到远层

    近层容纳较短的 trace。远层能存超过近层长度上限的项，两层可采用不同的容量与时序预算。

  3. 预测后读取远层

    预取控制器预测某条 trace 将执行时，可先访问远层。读出的长项进入支持相同长度的快速预取缓冲。

  4. 在前端请求时供给

    实际执行路径与预测一致、数据又及时到达时，前端可从缓冲取出 trace。数据晚于前端请求时，能隐藏的等待会变少。

示例

初始条件
假定近层最多存 8 条指令，远层最多存 16 条。A 有 6 条指令，跨内部跳转的 B 有 12 条。预测 B 的提前量足以完成远层读取。
处理结果
A 可存近层。B 存在远层，并预取到支持 16 条指令的缓冲。实际请求 B 时，缓冲可提供完整的 12 条。
结果解读
8、16、6、12 是算例长度。要衡量收益，需在前端请求 B 时检查数据是否已在缓冲就绪。

收益与代价

何时有效
长路径反复出现且能提前预测时，前端有机会一次取得跨越分支的指令。
代价和限制
长项占用更多空间。未执行的长项会占用远层端口和快缓冲，预测发得太晚则仍有远层等待。
验证指标
分别统计近层和远层命中率、长项预取正确率、预取到使用之间的提前拍数，以及前端每拍收到多少有效指令。

权利要求与出处

独立权利要求为第 1、11、17、19 项。下方列出部分权利要求的中文释义。

权 1
两层 trace 存储的最大长度不同，远层支持更长的 trace。控制器预测后发出预取，再由能够容纳长 trace 的缓冲向前端供给。
权 19
装置权利要求对不同长度 trace 的存储安排另有限定。

原文位置

独立权利要求 1
两层 trace 存储的最大长度不同。控制器预测未来会执行的 trace 并预取，缓冲也能容纳远层支持的长项。
说明书图 11–14
图中给出了分层存储、签名预取、快速缓冲和可存长 trace 的阵列。
独立权利要求 19 的场景边界
这一项单独限定较长宽度的顺序取指。权利要求 1 对预取缓冲有自己的限定。
