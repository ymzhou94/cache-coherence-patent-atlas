支持多种长度的分层 trace cache

Trace cache that supports multiple different trace lengths

工程要点

预取器把预计会执行的长 trace 从较远层取到能容纳该长度的缓冲，再由缓冲给前端供指令。

成立条件
轨迹可含内部已跳转控制转移。长项为远层和缓冲所支持，只有及时到达才覆盖需求等待。
验证方法
固定前端实际分支路径与远层读延迟，比较按需读取与提前读取该长 trace。记录前端首次需要它的拍、整条轨迹可供给的拍，以及实际消费的指令数。

工作机制

遇到已预测为跳转的分支，接着执行的指令可能跨越连续地址范围。trace 按执行路径组织指令，可以把转移前后的指令放在同一条路径中。

trace cache 分层保存包含内部已跳转分支的指令路径。较远层能存更长的 trace。控制器预测某条 trace 将执行时，可先从远层读出，把它放进支持该长度的预取缓冲供前端取用。

  1. 识别可构建的路径

    I-cache 按连续地址保存指令。前端按 trace 的构建条件识别执行路径，这里的 trace 包含内部 taken 分支。

  2. 把长项放到远层

    近层容纳较短的 trace。远层能存超过近层长度上限的项，两层可采用不同的容量与时序预算。

  3. 预测后读取远层

    预取控制器预测某条 trace 将执行时，可先访问远层。读出的长项进入支持相同长度的快速预取缓冲。

  4. 在前端请求时供给

    实际执行路径与预测一致、数据又及时到达时，前端可从缓冲取出 trace。数据晚于前端请求时，能隐藏的等待会变少。

权项与实施例约束

权 2 把从预取缓冲提升到近层限定在近层可容纳的长度内。权 3 允许远层主条目保存前段，并用指针指向溢出缓冲中的其余指令。

工程推演与验证

收益与开销

把远层轨迹放进预取缓冲时，溢出的后段也必须取得，才能交付完整长轨迹。若复用的是超过近层上限的长项，重复预测仍可能反复占用远层读取端口。

边界场景

若多个长循环在相同短时间内交替被预测，完整轨迹可能已经从远层读到缓冲，却在实际取用前被替换。此时远层的高命中率可以与前端等待同时出现。

条件推演

初始条件
假定近层最多存 8 条指令，远层最多存 16 条。A 有 6 条指令，跨内部跳转的 B 有 12 条。预测 B 的提前量足以完成远层读取。
处理结果
A 可存近层。B 存在远层，并预取到支持 16 条指令的缓冲。实际请求 B 时，缓冲可提供完整的 12 条。
结果解读
8、16、6、12 是算例长度。要衡量收益，需在前端请求 B 时检查数据是否已在缓冲就绪。

关联专利

  • 把二级 trace cache 的轨迹提前送到前端

    US12547409B2 的近层与远层允许不同的轨迹长度，远层返回需进入可容纳长轨迹的预取缓冲。US20250315262A1 用执行路径中指令地址形成签名，预测是否要从二级轨迹缓存预取。对照时分别量取预测可提前多少周期，以及返回后前端等待轨迹交付的周期。

  • 按内部控制转移的稳定性构建轨迹

    US12530193B2 根据内部控制转移的偏向决定哪些指令能够保留在轨迹中。US12547409B2 规定近层和远层支持不同最大长度，较长轨迹由预取缓冲向前端交付。前者改变可构造的轨迹组成，后者决定长轨迹可以存在哪一层以及怎样返回。

  • 预测 trace cache 未命中时关闭数据读

    US18/627,035 与 US18/627,001 在各自说明书记载的关联申请中互相引用。前者权 1 在预测缺失时抑制本次数据阵列读取，后者权 1 用预取缓冲区向取指前端提供来自二级轨迹缓存的长轨迹。
