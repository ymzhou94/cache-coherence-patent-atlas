分层 trace cache 如何向前端提供更长的取指组

Trace cache that supports multiple different trace lengths

靠近取指前端的 L1 trace cache 只能保存较短的条目。更长的 trace 应存在哪里，怎样在需求到来时完整送入前端？

核心结论

较远的 L2 可以把长 trace 分成主阵列与溢出存储两段。预测到将使用时，先取出并组装到更宽的 fast array。长条目由 fast array 直接供给，短条目才可能晋升到较窄的 L1。

L1、fast array 和 L2 分别解决什么问题

普通 I-cache 按连续地址缓存指令。trace 可把预测 taken 分支前后的指令连到同一取指组。图 1 的近端 L1 trace cache 按最多 N 条指令设计，较远的 L2 可以保存更多条目或更长的条目。每次需求都等较远的 L2 读完，可能超出前端的取指时限。

中间的 fast array 容纳最多 N＋M 条指令，说明书给出占用较少条目数的设计。匹配的长 trace 可以从这里直接供给前端，短 trace 可在显示有用后晋升至 L1。图中的三个来源汇入指令缓冲。权利要求 5、13 涉及普通路径用一项、长 trace 用多项的接收方式。

预取提前量要覆盖查找、组装和写入

图 2 从路径签名开始。签名可以由取指地址历史生成，lookahead 用匹配表项和置信度预判未来会访问哪条 trace。训练的一个例子是见到 L1 缺失但 L2 命中就累计相应签名的证据。

达到置信门槛发出预取后，L2 仍要读数据。长条目还可能先取指令前段，再定位尾段并组装。完整条目进入 fast array 后，需求到达且匹配地址时才能用它。该过程和短条目是否晋升 L1 是分开的控制。

为什么 L2 的溢出指针不应留到需求路径上

图 3 放大一条长 trace。L2 主条目保存前 N 条以内的指令、扩展标志和尾段指针。扩展标志没置位时无需访问尾段。对于长条目，溢出存储保留剩余指令，硬件沿指针取回并补到对应前段之后。溢出区满时，说明书允许选择逐出或缩短后只留在主阵列。

fast array 的条目可以保存完整宽度。把指针查找和前后段拼接放在预取阶段，可在需求命中时直接得到完整的指令组。扩展标志仍用于区分是否能装入窄 L1。若前端用原有的窄缓冲条目，可以将一条长 trace 写入多个条目。

地址匹配、及时到达和接收位置缺一不可

表 4 固定普通取指服务和总工作量，只变动预取地址、发出时间及前端可用条目。提前四个周期足以让这一模型中的数据在需求时到位，实际提前量还受 L2 访问、溢出读、预取仲裁和缓冲容量影响。

本模型把迟到和取错都归到普通取指路径，它们会占用已有预取请求的 L2 带宽。要判断供给是否改善，观测应包含需求时可用的长条目比例、进入指令缓冲的有效指令数、占用条目数和错取流量。只统计预测命中率无法区分这些条件。

宽顺序取指组还需要表示第一个 taken 分支

L2 的宽条目还可保存由预计 not-taken 分支连接的连续指令组。这类条目与有内部 taken 分支的长 trace 是不同用法。顺序组里的稳定 not-taken 分支和不稳定但预计 not-taken 分支可各自受限。说明书还允许跟踪两类条目的使用情况，决定保留与逐出。

图 5 将原图 16、18 的状态编码展开为等价逻辑判定：按程序顺序，首条 taken 分支即决定该取指组的去向，后续分支不再影响出路。因此三个候选分支只需四种方向结果，再分别编码强、弱置信度，硬件可直接从表项读出。

需注意说明书 0209 有一处写作 predicted-taken，图 5 的适用条件以原图 16、18 及权利要求 6–10、14–16 对顺序取指组的限定为准。

独立权利要求与具体宽度实现

独立权利要求 1、11、17 覆盖两级不同长度的 trace 存储与可支持较长条目的预取缓冲。权利要求 2 约束能晋升的长度，权利要求 3、4、12 描述尾段指针，权利要求 5、13 描述接收缓冲占用。权利要求 6–10、14–16、18、19 涉及宽顺序组及分支状态。

独立权利要求为第 1、11、17、19 项；全文核对覆盖 375 个说明书归档段与 19 项权利要求。
