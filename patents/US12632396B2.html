用启动密钥改变 AP 到 DRAM 的物理行映射

Mitigating row hammer attacks through memory address encryption

访问同一个逻辑内存地址时，怎样让 AP 的正常读写仍一致，同时降低固定 DRAM 行映射被跨设备复用的风险？

核心结论

在地址生成和 DRAM 选行之间用启动密钥变换地址位，DRAM 直接从输出选择物理行。不同设备或后续启动可以采用不同映射。实现位置可在请求源、控制器或内存器件。

要隐藏的是逻辑地址与物理行之间的固定关系

0032–0039 将映射明确接到 application processors、CPU cluster LLC、AP 互连与 LPDDR 控制器。0056 和 0068 列出电池供电移动端及手机实施例。独权落在 DRAM 选行和带秘密值的地址变换。

DRAM 行受到相邻活动干扰时可能发生数据错误。专利的防护针对软件地址长期对应固定物理行所带来的可预测性。图 1 描出 CPU cluster 到 LPDDR 的地址通路。内存控制器中的变换把正常访存地址映射到实际存储行，同一阶段内的读写仍使用一致的映射。

如果变换后的地址用于选择 bank、rank 和 channel，映射还可能改变控制器的并行度和行缓冲命中率。权利要求 1、10 要求用输出选行而且不在选行前解密。

映射放在 CPU cluster、控制器或 DRAM，接口代价不同

图 2 区分三种位置。靠近发起方时，CPU 或外设旁的映射电路可以复用已有翻译缓存的思路；多源必须处理共享地址的表示。集中放在控制器时，各源可先把常规请求发到 AP 互连。放在 DRAM 内部时，原文还列出通道、sideband 或器件内密钥源。

这些位置会让关键路径和密钥分发范围发生变化。说明书允许用类似 TLB 的结构缓存映射，也允许用轻量变换减少处理延迟，未给出具体产品的时序和带宽。

密钥更换的已披露时机与数据持久边界

图 3 用两个初始化阶段说明一项独权要求。权利要求 1、10、15 都要求初始值使用后改变映射。说明书具体展开 cold boot。若在活跃 DRAM 数据仍需保留时切换，工程上要处理数据可达性与读取一致性，说明书未给出对应迁移协议。

图 4 分开了地址映射和数据内容加密。只变换地址时，数据可原样通过。另一个实施例允许加密写入内容并解密读出内容。两者对面积、访问延迟和并行吞吐量的作用应独立评估。
