核心结论

目录为缓存块分配条目时，将该条目所在的路或路子集发给各持有代理。代理逐出时连同块标识返回指示。目录缩小搜索范围后仍核对当前块和持有者，再决定如何更新。

目录生成的指示随缓存块送给两个代理

图 1 左侧从代理看到回填通知，右侧看一致性目录分配条目。第一次存入 X 时，目录为 X 在某一路建立条目并记录 A 是持有者。B 随后缓存 X 时，目录只把 B 加入同一条目。两个代理在各自缓存中同时保存 X 和能定位 X 目录项的指示。

目录的路和代理本地数据缓存的路各有自己的组织与寻址。指示的作用范围是目录。说明书 ¶0085 允许代理的指示字段宽度不同，例如 A 的 1 bit 能指示两路组成的子集，B 的 2 bit 能精确找到其中一路。两种编码都能限定搜索范围。

逐出第一份与最后一份副本对应两次更新

图 2 跟踪同一个 X 的两次逐出。A 先释放本地块并把块 ID 与指示返给目录。目录在指示的路子集查找 X 后发现 B 仍持有副本。从持有者记录删除 A 即可。一致性目录项此时继续服务 B。

B 后来逐出最后一份副本时，目录再次查找 X，并确认没有其他持有者。此时 X 的目录项才可失效并用于别的块。表 3 按是否收到指示及其覆盖范围列出候选路读操作。目录路指示不提供当下的有效性和所有权结论。

什么时候收到指示也不保存

图 4 以 CPU 核发起回填为例。说明书允许对每颗核编程启用位。启用时按实现把指示写进缓存 tag，或用缓存 tag 索引一张独立的目录路指示表。禁用时可以收到但忽略指示，块的回填和目录分配照常发生。

以后逐出该块，如果消息没有指示，目录需要搜索所有路。原图 5 还显示新块可重用代理的本地缓存槽，旧块的指示进旧块逐出消息，新块从目录收到自己的指示。两个目录项不必位于同一路。

旧块写回遇到目录槽复用时怎样避免误更新

图 5 对应原图 3B。A 发出的旧块 X 写回消息尚未到控制器，B 填入不同块 Y，目录释放了 X 的旧槽并把位置用于 Y。在处理覆盖前，控制器向 A 发 X 的写回并失效命令，A 的失效响应仍可携带 X 的写回数据。

原写回随后到达时，原指示可能仍指向同一组目录路，但当前条目已对应 Y。控制器丢弃旧写回请求，X 的数据由失效响应路径写入内存。即使稍后 B 在别的目录路重新缓存 X，A 也不在 X 的当前持有者集合。用块标识和持有者资格共同检查，可以解释为何不能仅以命中的目录路更新条目。

目录读操作数量和延迟需要分别测量

权利要求 1 关注多个一致性代理共享块时保存指示。权利要求 9 以回填通知描述目录项的分配与指示返回，权利要求 15 同时涉及旧块逐出与新块回填。搜索路范围和逐核启用分别在第 2、5、6、13、14、18 项等给出。

表 3 的 4、2、1 是该实施例下搜索的路数。在全路并行比较的实现中，减少活跃比较和 SRAM 路访问主要减少动态活动，查询时钟周期可能一样。另按目录路实际激活次数、tag 或指示表开销、带指示的逐出命中比例统计。原文未提供固定的延迟或能耗收益。
