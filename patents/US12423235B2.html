工程要点

目录首次分配条目时向持有该块的代理下发包含选中路的子集指示。

成立条件
指示约束目录查找范围。它随副本保存，逐出消息可同时携带块标识以供目录核对。
验证方法
对同一块生成后续持有者与逐出序列，同时记录目录选择的路、下发给各代理的指示和逐出返回字段。

工作机制

一致性目录可采用组相联结构，每组包含多路。若逐出通知只带块标识，目录可能要逐路比较同一缓存组的标签。回填时向代理返回的路提示，可以在逐出时用来缩小查询范围。

目录首次记录某块时，给它选一个 way，并向持有者发送覆盖该路的子集指示。此后缓存同一块的代理也可收到这项指示。代理逐出块时，把指示和块标识一起发还目录。

  1. 建立目录项并下发指示

    首个代理缓存 X 时，目录选中一个 way，记录 X 的持有者，并发送可覆盖该 way 的子集指示。

  2. 把提示发给之后的持有者

    第二个代理缓存 X 时，目录增加一条持有者记录，并发出相同目录子集的指示。各代理将提示与本地缓存块关联保存。

  3. 逐出时回送块标识和提示

    代理在逐出通知中同时发送块 ID 和 way 指示。目录只查相应的候选 way，再根据块 ID 确认实际条目。

  4. 更新持有者或回收目录项

    还有其他持有者时，目录只清掉发通知的代理。最后一个代理逐出时，目录项可以失效。若未带指示，目录可以并行查多路。

权项与实施例约束

权利要求 2 要求逐出消息同时携块标识与子集提示。权利要求 5 的提示可指向多路并在子集内并行比较，权利要求 6 又规定未带提示时使用全路搜索。

图解与对照

  • 子集指示随回填发给各缓存代理
  • 第一份逐出只更新持有者，最后一份可回收目录项
  • 目录槽复用后，迟到的旧写回如何处理
  • 用提示缩小搜索范围，再核对块 ID
  • 同一组八路目录比较几路

工程推演与验证

收益与开销

提示缩小同一次比较激活的路数，但并行比较原本就能同时发起。即使查找周期未变，比较逻辑的活动和跨代理保存的提示位也会重新分配硬件成本。

边界场景

若目录每次仍需激活整个存储组，而只有比较使能受提示控制，读阵列的能耗可能没有明显下降。权利要求写明搜索范围，阵列门控粒度属于实现决定。

条件推演

初始条件
假设某个目录 set 有 8 个 way。X 进入 way 5，A 和 B 各缓存一份，收到的指示都覆盖 way 4、5。A 随后逐出 X。
处理结果
目录只查 4、5 两个候选，并用块 ID 找到 X。它删掉 A 的持有者记录，留着 B。B 之后逐出时若无有效提示，目录可查 8 路并回收该项。
结果解读
8 路以及 4、5 的分组是示例参数。目录用提示缩小比较范围，再凭块 ID 匹配条目，并按持有者记录判断是否回收。

关联专利

  • 通过块追踪项过滤缓存一致性探测

    较早的权项在请求代理和一致性接口分别跟踪一组缓存块，代理查组状态决定要不要发探测。较新的权项在目录初次分配时把包含所选 way 的子集提示交给代理，逐出消息带回提示以缩小目录的块 ID 搜索。第一个节省消息，第二个节省一次已有消息触发的目录比较。

  • 组相联缓存的双重标签比较与路预测

    组相联缓存先用标签比较预测一路并启动数据读，再确认实际命中 way，误选时放弃原读。目录的候选子集随缓存块分配下发，逐出时由代理带回，目录在这几路中核对块标识。前者预测一次数据读该开哪路，后者把先前的目录分配结果作为后续查询的提示。

  • 优先由主共享副本向请求方供数

    US12423235B2 让缓存代理保留目录路子集提示，用于缩小后续目录查找范围。US11947457B2 利用目录中的共享状态选择优先供数的缓存代理。一个决策定位目录项，另一个决策选取数据来源。比较收益时区分目录访问开销与数据到达请求方的时延。
