协处理器指令交付前预取操作数

Coprocessor prefetcher

CPU 已经拿到协处理器的访存地址时，能否让操作数先进入协处理器可访问的缓存？

工程要点

CPU 先把协处理器指令所需的操作数地址给预取电路。预取电路可在该指令正式交付协处理器前发出取数请求。

成立条件
操作数地址须提前就绪。数据要在协处理器正式访存前回填，并留在它能访问的缓存中，才能减少等待。
验证方法
固定指令提交序列和缓存初态，对照协处理器按需取数与 CPU 先交付操作数地址。记录预取发出、指令交付、数据就绪、实际消费四个时点。

工作机制

同一条取指流可同时含 CPU 指令和协处理器指令。协处理器收到指令与拿到操作数是两个时点。

CPU 先将生成的操作数地址交给协处理器预取电路。预取器可在指令交付前发出取数请求，数据目标为协处理器可访问的缓存。协处理器仍按正式指令执行自身操作。

  1. 发送协处理器操作数地址

    CPU 识别混合指令流中的协处理器操作，并为可预取的操作数提供地址。

  2. 将预取请求送到缓存通路

    协处理器预取器以地址发请求。在权 1 要求下，此时对应指令尚未交付协处理器。

  3. 交付协处理器指令

    正式指令仍要送给协处理器执行，提前发出的动作只涉及操作数取数。

  4. 读取缓存中的数据

    若地址 A 的数据已回填且仍驻留，正式读可以命中。其他情况继续走正常缓存路径。

权项与实施例约束

权 2 允许预取电路位于协处理器内。权 5、6 进一步描述预取进入可由该电路访问、也可与 CPU 共享的缓存，操作数地址仍与对应指令分时交付。

工程推演与验证

收益与开销

提前把地址交给预取器可让缓存请求与正式交付重叠，数据占用的却可能是 CPU 与协处理器共享的容量。看协处理器命中时，还要检查 CPU 热数据是否被挤出。

边界场景

在共享缓存中反复预取大批矩阵操作数，同时 CPU 正读取能装下的工作集时，操作数虽可早到，CPU 的重复缺失却可能增加。两边完成时间要分别核对。

条件推演

初始条件
CPU 顺序取到普通指令和一条需要地址 A 的协处理器指令，地址 A 先于协处理器指令交付就绪。
处理结果
CPU 将 A 交给预取器后，预取请求可先进入缓存通路。协处理器随后收到指令并读取 A。
结果解读
协处理器端是否命中取决于预取回填相对于正式读的时间，也取决于缓存保留。
