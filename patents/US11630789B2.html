为什么中断先试已上电处理器，再启动断电候选

怎样少唤醒几个 CPU，同时知道选中的处理器是否能及时执行中断入口？

在第一轮 Soft，仅向已经上电的候选投递。所有 CPU cluster 都拒绝且仍有待处理中断时，第二轮 Hard 允许给断电候选上电。两级 Ack／Nack 把决定传回全局控制器，核内用 ROB 退休和 LSU 完成边界预测能否在时限内真正进入中断。

电源状态先筛掉候选，核内状态决定能否接受

外设把中断交给全局中断控制器。图 1 从全局侧看，一级请求先去 CPU cluster 中断控制器；从 cluster 内看，二级请求再去某个处理器。两级都按请求、接受应答（Ack）和拒绝应答（Nack）交互。首轮（Soft）筛掉断电的处理器，仍上电的处理器各自决定是否能在时限内进入中断。

图 1 的断电分支只在第二轮（Hard）打开。每个接到 Hard 的 cluster 中断控制器可以给本 cluster 内原先断电的处理器上电，再尝试投递。图上的核电源状态属于硬件供电状态。实际进入中断异常入口的时间要在处理器端另行记录。

一个候选返回拒绝，下一候选仍在当前轮次

图 2 给出权利要求 2、4、6 所述的串行实施例。CPU cluster A 的已上电处理器预计不能及时接收，向本地控制器发 Nack；全局侧收到的是整个 A 的 Nack。它随后选择 CPU cluster B，B 上已上电的候选返回 Ack。图中只设一个待处理中断，所以 Ack 结束当前投递尝试。若中断队列仍有项目，原图 3 可以先进入等待处理器取走中断的状态。

表 3 的两种 Nack 在不同控制层。某个核心拒绝时，先看本 cluster 还有没有候选；第一轮所有 cluster 均拒绝且仍有中断等待时，才进入 Hard。说明书还披露 Force，可在 Hard 仍未完成或一定超时条件下尝试多目标请求。不同实施例对 Force 的应答做法有差异。独立权利要求 1 写两轮，方法权利要求 19 还要求第一轮在多个 cluster 中断控制器间串行。

Ack 承诺及时进入可中断点，实际进入还要完成退休

图 4 沿核接口读到中断应答电路。重排序缓冲区（ROB）给出尚未退休的指令操作状态。访存单元（LSU）报告在途访存是否可能超时，并在实施例中交出 true LS NS pointer，定位其已承诺完成的非推测访存。应答电路据此判断已解析边界能否收拢；边界间有无法撤销的操作时，返回 Nack。

原图 8 的成功路径先发出 Ack，再冻结解析指针，并让退休指针追到该位置，最后进入中断。在途设备访存、尚未完成的长时延操作和屏蔽状态都可能缩小候选集合。说明书给出约 5 μs 作为一个时限例子，未规定各处理器的固定时间。比较投递收益时，应分别量中断请求至第一层 Ack、额外上电等待、Ack 至执行中断入口首条指令这几段。

同一轮次用尽本地和远端候选后，主控制器才会升级

权利要求 1 和 19 约束两个投递层级与第二轮扩大候选。权利要求 15 则单独约束处理器的应答电路，要求 ROB 和 LSU 都能在时限内到达同一可中断点。依赖长时延操作和设备地址空间的判定属于后续从属项。

图 5 换成三个裸片。远端 B 的从中断控制器先向主中断控制器上报中断；在本地先尝试的实施例中，主控制器依次发起本地 Soft、远端 B Soft 和远端 C Soft，直到收到 Ack 或各方都返回 Nack。每个远端控制器自行协调其 CPU cluster，返回的是本裸片的应答结果。

图 5 的三个 Soft 都拒绝，主控制器才从本地重新开始 Hard。此轮可给断电处理器上电。远端 B 最后返回 Ack，主控制器无需再把本次 Hard 发给远端 C。若两轮均用尽仍未投递，原图 10 还披露 Force。跨裸片评估可在图中逐一计入请求和应答往返，再与上电等待及处理器进入异常入口的时间对应。
