Maintenance Operations for Hierarchical Trace Cache

一条 trace 可能跨页。收到指令缓存失效、地址转换失效或权限变化时，前端怎样保留其余有效的 L2 trace？

核心结论

写入 L2 trace cache 时记录每个取指组关联的页信息。指令缓存失效按物理页查 Bloom 过滤器并走查旁路散列表，TLBI 按虚拟页筛选后走查，权限变化则可在预取 trace 之前查权限表。当前端暂缓使用未经核验的条目，只需处理与维护有关的 L2 内容。

指令缓存失效以物理页查找一条 trace 的所有组成部分

Trace cache 缓存沿一条预测执行路径拼接的指令组。原图 19 的两级 trace cache 允许从 L2 预取到前端快速缓冲。若 trace 内部的跳转分支跨页，仅检查入口 PC 会漏掉后续取指组。指令缓存失效可能由若干同页缓存行的维护命令组成。合并缓冲按物理页号（PPN）把同页请求归成一次检查。

图 1 对照原图 22。从 L2 写入事件取出所有取指组的 PPN，散列后同时写 Bloom 过滤器和按 trace 组织的旁路静态存储器（SRAM）。普通 trace 标签可按虚拟地址标记，旁路 SRAM 为走查提供物理页的散列。维护请求命中过滤器才有走查。走查使散列匹配的条目失效，并用保留项重建过滤器。

TLBI 用虚拟页筛选，在走查窗口控制 L2 读取

原图 21 的地址转换缓存失效（TLBI）缓冲非空时，可暂时阻塞 L2 trace cache 与签名预取活动。写入 trace 时，各取指组对应的虚拟页号（VPN）散列均会置位。

过滤器命中表示至少有一条 trace 可能包含目标 VPN，硬件随后逐条读取有效项并核对实际保存的 VPN；过滤器未命中则可直接跳过本次 L2 走查。当缓冲溢出时，原文允许清空整个 L2 trace cache。

图 2 单独标出暂停、走查、重建与可恢复读取的顺序。完整走查期间可以暂停预取。另一实施方式可记录进度，只允许访问已经走查并保留的前缀。表 3 对比三类操作使用什么键，以及哪个阶段决定结果。第 1、13 项限定在所列维护操作中选定一部分有效 L2 条目失效，第 19 项写的是决定是否失效层级中的缓存数据。

哪些 trace 会因物理页散列碰撞而失效

图 4 展开 trace A 的两个取指组。只有后续组在目标页 P7，逐组比较仍可使整条 A 失效。如果另一条 B 的取指组在 P9，且 h(P9)=h(P7)，按散列匹配也会使 B 保守失效。走查保留所有组均不匹配的 trace，并用保留项重建过滤器。原图 21 的 TLBI 走查可以再比较完整 VPN，那个实现中 Bloom 假阳性可增加走查而不增加这一类误失效。

图中的散列值与地址均为模型输入。过滤器减小维护开销的上限取决于过滤器命中率和误命中率。如果写入历史不及时重建，逐出和失效残留的置位也会增加无谓走查。前端恢复后的收益应由幸存 trace 的再次命中、重建和取指缓冲欠供等观测量验证。

执行权限在哪个边界被重新检查

原图 23 在 L2 trace cache 旁为每个取指组保留权限表索引。预取控制器从同一条目的这些索引查当前权限。在图 5 中，所有组权限满足时才允许向 L1 预取。某组不满足就阻止这一传输，L2 条目仍可保留。原文允许权限更新时清 L1，所以仍在 L2 的指令字节与可交给前端执行是两个状态。

这个方式要求恢复供给前已看到当前权限。第 2、14、20 项写检查 trace 的多个取指组对应的页权限，第 3、15 项再要求追踪权限信息的位置并在向 L1 预取前核验。原文未给出权限表可容纳的页数、同步协议周期或实际应用中的额外功耗。
