按页定位二级 trace cache 的失效范围

Maintenance Operations for Hierarchical Trace Cache

内核触发取指缓存维护时，如何避免二级 trace cache 每次全清？

工程要点

维护电路把取指组的哈希物理页号放入过滤器，并随二级轨迹表项保存。过滤器命中后扫描二级轨迹，找出匹配项并据扫描结果重建过滤器。

成立条件
这是与物理页号关联的维护路径。跨页轨迹要检查其各取指组。哈希碰撞可带来额外扫描。
验证方法
预放相同的跨页和单页轨迹，分别运行全量二级失效与按页筛选。检查目标页关联轨迹是否都被清除，记录扫描条目数、保留的轨迹数及首次重新取指延迟。

工作机制

一条指令轨迹（trace）可能由不同物理页上的取指组组成。维护操作影响其中任一页，就可能使已解码或合并的轨迹不再可用。

维护逻辑按操作类型核对缓存或地址转换变化。对指令缓存失效的一个实施例，二级 trace cache 保留取指组的哈希物理页号并以过滤器判定是否需要扫描。命中后扫描，失效匹配轨迹，并重建过滤器。

  1. 记录二级轨迹覆盖的页

    二级存储写入轨迹时，过滤器记录相关取指组的物理页哈希。

  2. 按维护类型查询候选

    维护操作送来目标页信息。指令缓存失效与地址翻译维护的索引可不同。

  3. 检查二级轨迹标签

    在过滤器命中时扫描二级条目，按哈希物理页号检查要失效的轨迹。

  4. 分别处理一级和二级

    权 16 的方法先全部失效一级，再由过滤器确定二级部分。

  5. 重建过滤器

    扫描后依据剩余的二级轨迹重新填充过滤器，供后续维护查询。

权项与实施例约束

权 3 把二级轨迹覆盖各取指组的页权限信息位置也纳入跟踪，可在预取至一级前核验。权 4 的维护路径还可以整刷一级，再确定二级失效范围。

工程推演与验证

收益与开销

一级整刷和二级选择性保留可以同时发生。只看总保留数会隐藏一级短期缺失，物理页哈希筛选能减少部分扫描，却仍可能触发整段二级遍历和过滤器重建。

边界场景

若很多长轨迹都跨过同一个频繁更新的热代码页，按页定位即使准确也可能保不住这些二级项。此时还要承担扫描和重建的工作，选择性失效未必更快。

条件推演

初始条件
轨迹 X 由物理页 P 和 Q 上的取指组组成，轨迹 Y 只覆盖物理页 R。软件更新物理页 P 上的代码并触发对应缓存维护。
处理结果
二级过滤器命中页 P 后，维护逻辑检查并失效匹配轨迹 X。轨迹 Y 可保留，除非发生其他失效条件或哈希碰撞。
结果解读
判断作用范围时要看轨迹覆盖的所有取指组，不能只看轨迹入口 PC。

权利要求与出处

独立权利要求为第 1、13、19 项。下方列出部分权利要求的中文释义。

权 1
分层 trace cache 对指令缓存失效、TLB 失效或权限变化可只失效二级 trace cache 的一部分。
权 8
用哈希物理页号填充过滤器，命中后扫描二级 trace cache，确定候选并重建过滤器。
权 16
一种方法对一级 trace cache 全部失效，并用过滤器确定二级失效范围。
