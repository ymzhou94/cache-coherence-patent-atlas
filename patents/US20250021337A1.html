普通取指与 trace 尾部分支共享方向预测表

Sharing Branch Predictor Resource for Instruction Cache and Trace Cache Predictions

一个 trace 跨多个取指组时，如何预测末端的控制转移，又避免为 trace 路径复制整套预测表？

  • 核心结论
  • 普通取指组和 trace 末端分别接到同一预测表
  • TAGE 表在标签与位置字段处区分用途
  • 区分末端方向、下一取指地址与历史更新
  • 内部的较不稳定 CTI 可重用其原有 lane
  • 权利要求与出处
  • 关联专利

核心结论

普通分支 lane 继续从预测表取得组内方向，额外的 trace lane 从同一表取得 trace 末端方向。TAGE 的实施方式用基础表专用字段和可共享的高级表区分两类预测。

普通取指组和 trace 末端分别接到同一预测表

原图 1、7、8 将方案放到 CPU 取指前端 I-cache、trace cache 与方向预测的交互处。原图 17–18 给出 AP 计算单元所在 SoC 与手机场景。

普通取指和缓存 trace 提供的指令数不同。图 1 画出普通组内方向与 trace 末端方向的两类 lane。尾部 lane 可用 trace 起始取指组的地址查询跨多个先前组的末端 CTI。

独权 1 规定缓存 trace 包含多个预测 taken 的控制转移，并让两类 lane 访问同一预测表。是否有足够物理读取端口，以及每拍可并行多少请求，需要看实现。

TAGE 表在标签与位置字段处区分用途

图 2 对应原图 8。基础表给 trace 路径独立字段；多级带标签表的命中逻辑使用普通组的位置与 trace 类型。某些实施例用固定位置值避免同一条目的解释重叠。

外部共享可以减少复制表项，但不同类型之间的容量竞争必须计入。独权未规定 TAGE；从属权项 4、14 和 20 才加入基础表与多级表。

区分末端方向、下一取指地址与历史更新

共享表给的是 CTI 方向。图 3 的 trace NFP 可以另给 trace 后的取指地址，普通 NFP 给当前组后的地址。预哈希历史 token 是原图 6 的一种附加机制，支持跨越多个内部控制转移。

普通地址路径与 trace 地址路径可以并行读出。只有预测与所取指令源吻合，跳过中间组才有意义。

内部的较不稳定 CTI 可重用其原有 lane

图 4 对应原图 12。如果某实施例允许较不稳定的非终结 CTI，缓存条目位置字段可以选择原来用于普通取指组的 lane。trace 末端方向仍由专用 lane 提供。这样可以避免对这条内部 CTI 重复配置一套预测查询。

允许内部 CTI 跨入 trace 会增加意外退出。需要看继续沿 trace 的预测准确率、退出后重新取指的次数，以及两类访问的表项竞争。
