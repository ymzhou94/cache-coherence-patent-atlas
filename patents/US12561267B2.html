CPU 和 GPU 通过独立片上网络访问内存

Multiple independent on-chip interconnect

CPU 核簇的最后级缓存和 GPU 访问同一系统内存时，在哪一层隔离流量？

工作机制

混合 CPU、GPU 和 I/O 的片上网络可能让不同流量竞争同一组交换资源。专利把互连拆分为多套网络，这些网络可以在内存控制器处汇合。

CPU 核簇和 GPU 分别连接物理、逻辑独立的交换网络。内存控制器分别直连两套网络，承接双方的系统内存访问。另一系统权项再增加独立 I/O 网络。

  1. CPU 核簇发出访问

    该权项规定核簇含两个或多个 CPU 及共享 LLC。访问系统内存走 CPU 网络。

  2. GPU 发出访问

    GPU 的内存请求走独立交换网络。

  3. 内存控制器接收两路流量

    控制器分别直接连接两套网络，承担对系统内存的访问。

  4. 区分互连隔离与 DRAM 共享

    互连端独立，汇合之后仍应按系统内存资源做带宽与延迟分析。

示例

初始条件
一个 CPU 核簇对系统内存发起读，同时 GPU 发出一串读请求。
处理结果
两类请求途经不同的交换网络。到达同一内存控制器后，可以再次竞争其下游资源。
结果解读
如果 CPU 的延迟仍升高，应分别检查控制器入口、DRAM 命令队列和通道占用。

收益与代价

何时有效
相互独立的交换资源可以减少 CPU 与 GPU 在片上网络侧的直接争用。
代价和限制
多个网络仍在内存控制器或系统内存汇合，端到端访问可能受共享队列、通道带宽和 DRAM 调度限制。
验证指标
分别测片上网络的排队时长与内存控制器的排队时长。在相同 CPU 访问流量下扫描 GPU 带宽，比较 CPU 访问尾延迟。

权利要求与出处

独立权利要求为第 1、8、14 项。下方列出部分权利要求的中文释义。

权 1
带最后级缓存的 CPU 核簇与 GPU 分别经过两套独立的交换网络访问由共同内存控制器管理的系统内存。
权 8
系统 SoC 增设独立 I/O 网络。CPU、GPU、I/O 三套交换资源分别连接内存控制器。
权 14
对应方法权利要求分别规定两套网络上的系统内存通信。

原文位置

权利要求 1、14
具体要求 CPU 与 GPU 网络物理、逻辑独立，并由同一内存控制器接入。
权利要求 8
以第三套独立 I/O 网络扩展拓扑。
