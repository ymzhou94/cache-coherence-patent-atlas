CPU 和 GPU 通过独立片上网络访问内存

Multiple independent on-chip interconnect

CPU 核簇的最后级缓存和 GPU 访问同一系统内存时，在哪一层隔离流量？

工程要点

CPU 核簇和 GPU 分别走独立的片上交换网络，各网络直连共享的内存控制器。

成立条件
交换资源独立，负载仍可在共享控制器或 DRAM 上竞争。
验证方法
固定 CPU 的缺失读流，分别开关 GPU 的持续内存流量。按网络口和控制器入口分别记录队列等待与实际服务周期。

工作机制

混合 CPU、GPU 和 I/O 的片上网络可能让不同流量竞争同一组交换资源。专利把互连拆分为多套网络，这些网络可以在内存控制器处汇合。

CPU 核簇和 GPU 分别连接物理、逻辑独立的交换网络。内存控制器分别直连两套网络，承接双方的系统内存访问。另一系统权项再增加独立 I/O 网络。

  1. CPU 核簇发出访问

    该权项规定核簇含两个或多个 CPU 及共享 LLC。访问系统内存走 CPU 网络。

  2. GPU 发出访问

    GPU 的内存请求走独立交换网络。

  3. 内存控制器接收两路流量

    控制器分别直接连接两套网络，承担对系统内存的访问。

  4. 区分互连隔离与 DRAM 共享

    互连端独立，汇合之后仍应按系统内存资源做带宽与延迟分析。

权项与实施例约束

权利要求 5 的网络接口可以把代理消息转换为所在网络的格式；权利要求 6 允许 CPU 代理和 GPU 代理经特定第二网络交换机通信。

文中术语
虚拟通道
复用同一物理网络时，为某类报文提供区分的流量身份和队列资源，定序与服务质量可按其定义。

图解与对照

  • 独立交换后仍进同一控制器
  • 两套交换网络汇合在内存控制器
  • CPU、GPU 和 I/O 分别选哪个网络
  • 两套网络按不同条件保证定序

收益与开销

分别观测 CPU/GPU 网络、跨代理消息接口和内存控制器的排队时长。并行传输最先影响网络队列；端到端延迟取决于最拥塞的共享环节。

边界场景

GPU 大量访问同一个 DRAM 控制器的通道时，CPU 缺失读仍可能排队。这是从共用内存控制器推得的性能边界，基线应固定控制器地址映射。

条件推演

初始条件
一个 CPU 核簇对系统内存发起读，同时 GPU 发出一串读请求。
处理结果
两类请求途经不同的交换网络。到达同一内存控制器后，可以再次竞争其下游资源。
结果解读
如果 CPU 的延迟仍升高，应分别检查控制器入口、DRAM 命令队列和通道占用。
