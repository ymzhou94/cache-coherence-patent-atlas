CPU 与 GPU 各走一张片上网络，共用内存控制器

Multiple independent on-chip interconnect

核心结论

专利用不同的交换节点和物理连线构成 CPU 网和 GPU 网，两张网都直接接入共享内存控制器。多网络代理可按事务类型选网络，再按优先级等属性选虚拟通道。交换网络里的资源分开以后，控制器与外部内存仍是共享位置。

独立交换路径到哪里会合

图 1 从一个内存控制器反看三条路。CPU cluster 的多个核心共享给定 LLC，内存事务经 CPU 网的交换节点送来。GPU 经另一组节点和物理连线到同一控制器。I/O 在说明书实例中也有独立交换路径。不同网可采用不同拓扑，原图 5–8 以 CPU 和 I/O 两个环、GPU mesh 举例。

权利要求 1、8、14 的共同重点在于独立连接和共享控制器。环与 mesh 见第 10、20 项，GPU 网是否非一致性见第 11 项。降低某段互连排队也可能把瓶颈移到共享控制器，应分别记录入端排队和 DRAM 服务时间。

哪些事务到不同物理网，哪些只换虚拟通道

图 2 的 CPU cluster 同时接入两张网。例如一致性内存访问选 CPU 网，针对设备空间的 PIO 选 I/O 网。若同一物理网提供低延迟事务（LLT）和 bulk，代理可以按紧急程度等属性选择虚拟通道。虚拟通道属于已选的网络。

说明书把普通内存流量、低延迟内存、实时内存与面向设备的非内存消息分开。原图 12 的常规实施例把 RT 与 VCP 放在 I/O 网。第 26、27 项描述虚拟通道数量与类型可以不同，源文也允许为配置用途另行使用通道。图 2 采用原图 12 的常见路径。

先发的读还没完成，后发读什么时候可以先返回

图 3 将结果准备时间和协议交付时间分成独立轨道。第 17 项用同一源、目的和虚拟通道限定有序通信。第 18 项在另一张网用同一源、目的和地址块限定有序。说明书给出的细化还能按子通道划分流。

两读地址块不同时，R1 已准备好就可能先交付。两读属于同一个要求有序的域时仍需等待。表 5 只推导这些排序结果，实机延迟还要测链路、队列与共享内存控制器。

跨裸片是否会换到另一张网络

图 4 把原图 9 按网络分开。CPU 与 I/O 环在两侧裸片之间分别延伸，relaxed-order 网络也可扩展。可选裸片接口电路把同类网络的交换节点接起来。第 24、25 项涉及多个裸片及连接。一个 CPU 访存如果目标地址落在另一裸片，仍可沿其 CPU 网络访问目的控制器。

从源端的角度，网络标识可以跨裸片保持一致，物理路径仍多经过裸片接口和链路。评估可分别测同片与跨片请求到相同逻辑终点的时间。单裸片实施例可采用局部闭合环、菊花链或不使用跨片链路。
