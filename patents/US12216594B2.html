工程要点

控制器按两个 rank 的待处理读数分配本轮读槽位，按服务质量要求决定该轮内的 rank 切换次数。

成立条件
槽位分配和 rank 切换约束是在同一读轮次确定的两个量，需分别观测。
验证方法
保持两个 rank 的到达序列不变，仅改变服务质量约束。记录每 rank 分得槽位、服务次序、切换次数和第一笔读等待。

工作机制

同一个读轮次可服务两个 rank。过于频繁的 rank 切换消耗总线时序裕量，只按一种请求来源服务又可能延长另一侧等待。

控制器按两个 rank 的待处理读请求数分配本轮的读槽位，并用服务质量约束确定本轮允许的 rank 切换次数，然后执行已分配的读。

  1. 按目标 rank 对请求分类

    两个请求子集分别对应两个共用物理总线的 rank。

  2. 在读轮次起点分配槽位

    用两侧待处理数量为有限的读槽位分配额度。

  3. 确定 rank 切换次数

    按一项或多项 QoS 要求决定在本轮切换多少次。

  4. 执行分配结果

    仲裁器按得到的槽位和切换约束发出读请求。

权项与实施例约束

权利要求 5 至 7 分别以最老的低延迟请求、最多的低延迟请求和最少的低延迟请求选择起始 rank。首发选择发生在槽位分配以后，三种条件对应不同实施方式。

图解与对照

  • 先确定槽位和切换，再执行本轮读
  • 两个 rank 共用总线，由读仲裁器分配槽位
  • 双 rank 读仲裁的三项输入
  • 评价尾延迟时保留两侧统计

工程推演与验证

收益与开销

首发 rank 提前使用本轮分配的槽位，另一个 rank 则要等待首次切换。可在槽位和切换次数相同的原图 8、9 流程中记录各 rank 首次读命令与最老请求的读数据返回时间。

边界场景

若某个 rank 有一笔很老的低延迟请求，另一 rank 同时积压许多较新的同类请求，选最老请求会提前一笔而推迟另一侧。最老请求的改善与两侧各自的延迟分布需要一起看。

条件推演

初始条件
教学设定中读轮次最多允许六次读，rank 0 有四个等待请求，rank 1 有两个，其中一个具有时限。
处理结果
总槽位分配仍参考 4 与 2 的待处理量。时限可影响何时以及允许几次切到 rank 1。
结果解读
