一致性代理向应用加速器提供缓存状态

Coherent agents for memory access

工程要点

一致性代理收到请求后跟踪目标数据的状态变化，把更新过的状态交给应用加速器。

成立条件
代理采集的是一致性协议状态，加速器结合访问类型决定何时执行数据操作。
验证方法
给同一目标数据加入一次并发的缓存状态变化，比较有竞争与无竞争两组。记录访问请求、状态上报和加速操作发出的周期。

原文权利要求 6对应工程图解

工作机制

应用加速器替 CPU 或其他处理组件执行数据操作时，共享数据可能同时留在多个缓存。一致性互连负责约束可见性。加速器可以通过支持该协议的代理获得状态，再按操作类型决定如何访问。

一致性代理接收加速器访问请求，在互连上监测相关数据的使用状态。代理把状态交给加速器，后者依据访问类型与状态调整数据操作。一致性代理与应用加速器承担不同职责。

  1. 提交数据操作

    应用加速器把访问类型和目标数据交给一致性代理。

  2. 监测共享数据

    代理在一致性互连上取得相关缓存组件的使用状态。

  3. 返回状态更新

    代理把观测到的最新状态交给加速器。权利要求 6 明确包含状态更新。

  4. 根据访问类型推进

    加速器结合其操作与状态决定是否继续执行以及怎样执行。

权项与实施例约束

权利要求 3、4 分别限定加速写取得唯一访问和加速读取共享访问。共享读允许其他组件仍读取该数据，唯一访问期间则限制相关组件的修改。

图解与对照

  • 状态更新先于加速操作
  • 一致性代理位于加速器和互连之间
  • 不同参与方负责哪些状态
  • 诊断时分开观察三段延迟

工程推演与验证

收益与开销

状态监测让加速器知道怎样合法访问缓存数据。共享读可保留读取并行性，频繁交接唯一写权限则需要一致性消息与等待。测量须分开记录读和写获取权限的延迟。

边界场景

若任务只对同一地址反复执行写，而 CPU 持续修改该地址，加速器可能花更长时间等待唯一权限。这个等待取决于其他组件的访问行为，权利要求 3 并不提供固定上界。

条件推演

初始条件
组件 A 缓存共享数据 X。加速器收到一笔涉及 X 的读或修改请求。
处理结果
一致性代理先取得 X 的使用状态，再通知加速器按访问类型继续处理。
结果解读
示例只跟踪状态传播。具体等待规则和总延迟取决于采用的一致性协议。
