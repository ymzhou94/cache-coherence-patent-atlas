按工作完成窗口选择 CPU 性能状态

Provisioning of performance states for central processing units (CPUS)

工程要点

CPU 性能控制器估计一组工作完成窗口，识别负责完成这些工作的进程，再为已判定受截止时间约束的工作选用相应性能状态。

成立条件
以缓冲区交换推算窗口是实施例。周期或工作量变化时，负责进程的识别结果和每个窗口的截止时间都须重新检查。
验证方法
回放相同的进程活动和帧提交序列，对照利用率控制与按完成窗口选档。分别记录负责进程识别错误、提交前余量、迟交帧及每帧能耗。

工作机制

GPU 交换可见缓冲区和工作缓冲区提供了一条观测线索。CPU 并不直接从画面提交得知哪个进程应提速，仍需先识别负责人，再判断工作是否受期限约束。

控制器估计提交截止时间，识别负责工作的进程，再选择预计能在完成窗口内处理完工作量的 CPU 性能状态。部分实施例检测到受算力限制的长任务后，改用基于利用率的性能控制。

  1. 取得窗口边界

    图 1 的 GPU 可以在准备完工作帧时交换两个缓冲区。图 2 将相关时刻作为推定工作完成窗口的输入。

  2. 归属工作量

    跨窗口统计候选进程完成的工作。权利要求 3 的做法比较工作量方差，选择方差最低的候选。

  3. 按预留余量后的截止时间选择运行点

    设备可为窗口预留期限余量。图 5A、5B 给出在截止时间前可完成工作、且频率较低的性能状态。

  4. 按任务类型切换

    有稳定的工作完成窗口时，按提交截止时间选择 CPU 运行点。检测到算力受限的任务后，切换为按利用率选择运行点。任务结束后可恢复按窗口控制。

权项与实施例约束

公开权 5 把期限余量留在完成窗口之外。可搜索的运行点须让预计 CPU 执行时长落在扣除余量后的窗口内。余量一旦改变，低频可行范围也随之改变。

工程推演与验证

收益与开销

把完成延迟拆成可运行但未获 CPU 的等待、实际执行和提交前余量。提高频率主要改变执行段。若等待时间主导，只看 CPU 忙碌时间会高估余量。

边界场景

沿用图 5A–5B 的判决，保持平均指令量不变，交替注入长短帧。若运行点下降且提交前余量的 P1 分位转负，检查窗口或工作量预估的误差。

条件推演

初始条件
设窗口为 16 ms，保留 2 ms 余量。把低、中、高三档的预计完成时间取为 17、13、9 ms。
处理结果
有效期限为 14 ms。低档晚 3 ms，中档留下 1 ms，高档留下 5 ms。在中档能耗较低的前提下可以选择中档。
结果解读
这是按固定耗时比较档位的算例。窗口预测、执行时间估计以及误差余量得分别校准。

专利原文

关联专利

  • 利用帧提交前空隙预做工作或降低处理器功率

    两件都利用显示提交的周期性。US20250086009A1 在确认 CPU 进程承担周期性限时工作后，用估出的完成窗配置性能档，并为估计误差留下余量。US12361630B2 在剩余时间或较长的下一提交周期内，分别考虑预做预测操作或以更低功率档执行下一项操作。一个先找出本周期谁必须按时完成，一个把空余时间让给后续工作。

  • 非对称多处理器的闭环性能控制与热功率约束

    US20250086009A1 根据剩余工作量和截止时间估计按时完成所需的 CPU 性能状态。US11579934B2 汇总线程组推荐的运行点，再依据核簇功率映射与控制量上限确定可用运行点。若功率上限使实际运行点低于性能请求，仍须检查工作能否在截止时间前完成。
