用工作完成窗口选择 CPU 性能状态

Provisioning of performance states for central processing units (CPUS)

应用里有多个 CPU 进程时，控制器怎样找出影响帧完成的进程，并为它选择性能状态？

核心结论

性能控制器估计多个工作完成窗口，按窗口确定负责工作的进程并配置候选 CPU 性能状态。识别为截止时间约束型负载后，按该状态执行。图示实现可使用 GPU 帧缓冲交换作为窗口边界，在算力受限时切换为利用率控制。

GPU 缓冲交换给 CPU 工作窗口提供边界

GPU 把已完成的工作帧从工作缓冲切换到可见缓冲。帧缓冲可以将交换事件通知 CPU 性能控制器。控制器以两次通知所对应的时刻作为工作完成窗口的开始和结束。第 8 项明确了 GPU 的双缓冲，第 9 项进一步要求用交换时刻确定窗口。

图 1 上部画帧数据的流向，下部画控制器收到的完成时刻、进程观测和状态设置。说明书把控制器选择及配置性能状态的机制称为动态电压与频率管理（DVFM）。说明书允许估计窗口时采用目标帧率等性能要求。

先配置候选性能状态，再按负载类型应用

原图 2 的执行顺序是估计窗口、识别进程、配置性能状态、判定负载类型。截止时间约束型走候选状态，随后继续判定。算力受限型切换为基于利用率的控制，在该工作结束后返回性能状态配置。

说明书的一个算力受限判定例使用 CPU 单独执行所占比例，阈值举例为 90%。它表示该负载很少与 GPU 工作重叠，具体统计口径由实现决定。图 2 保留两条回路，便于区分持续监测与重新配置。

同一组窗口内，怎样识别负责完成工作的进程

第 3 项给出的识别方法是对每个候选进程分窗口估计完成工作量，再选方差最小的候选。原图 4 的不同进程可在同一窗口内多次执行，图 3 因此用共同窗口切割样本，并展示执行片段跨边界时该如何分窗。

图区分原图的示意与具体测量。算例用进程活跃时间近似工作量，三个候选的平均值相同，但每窗总量的方差不同。实际选择还受候选集合和观测量定义影响。若背景工作同样规律，仅凭低方差会有误判。

截止余量会改变可用的性能状态

原图 5A/5B 用近似恒定的工作量比较高频短时与低频长时两种状态。第 5 项允许从完成窗口扣除截止余量，再筛选符合期限的性能状态。图表 4 用 16 ms 窗口和 2 ms 截止余量演示，实际参与比较的期限为 14 ms。

在这个算例里，中状态和高状态可行。若希望比较能效，需要采样 CPU 电压、频率和实际功率，计算完成同一帧的能量。缓存、内存访问或 GPU 协同占比较大时，完工时间和功耗都可能偏离频率的简单比例。

用当前频率与完成时间查询下一个状态

说明书 [0036] 披露一种查表实施方式。图 5 左侧分别输入当前状态的运行频率 f₁ 与完成时长 t₁，以及扣除余量后设给下一状态的目标完成时长 t₂。查询用这三项数据寻找候选频率 f₂。性能控制器随后通过 DVFM 配置第二状态，CPU 在后续工作窗口执行已识别的进程。图表 4 的时限比较说明此查询可接受的完成时间范围。

原图 5A、5B 用近似相等的 f₁t₁ 和 f₂t₂ 表示完成的工作量相近。图中面积的量纲是运行周期，频率与完成时长近似成反比依赖工作量相近且每周期能完成的有效工作变化不大。受内存延迟、GPU 等待或频率切换影响时，估计可能偏离。比较能效还要计算活动到空闲的窗口总能耗，同时记录实际工作完成的位置。

权利要求与出处

独立权利要求为第 1、8、15 项；全文核对覆盖 55 个说明书归档段与 20 项权利要求。

独立权利要求

权利要求 1

CPU 估计完成窗口、找出负责进程并配置候选性能状态。确认工作受期限约束后才按该状态执行。说明书把按工作负载配置性能状态的机制称为 DVFM。性能状态是该机制的选择结果，权利要求未限定其具体电压或频率表。
