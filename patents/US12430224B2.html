缓存缺失追踪器在缓冲区不足时反压执行

Debug trace of cache memory requests

影响访存延迟的缓存缺失，怎样完整记录而不丢失追踪事务？

工程要点

调试模式下追踪缓冲空间不足时，追踪器把相关信息暂存在回填缓冲，并通知缓存停止发出新内存请求。

成立条件
停顿来自调试记录不足，可能改变本来要测量的缺失服务间隔。
验证方法
重放同一缺失流，分别保持追踪缓冲充足和使其耗尽。记录剩余条目、回填缓冲占用、缓存停顿信号及到下层的请求间隔。

工作机制

分析缓存缺失时，需要知道发出请求、命中判定和下游访问的关系。追踪缓冲区可能先耗尽。授权文本在特定调试模式中反馈停顿，保证收集路径能继续处理已选择的事务。

追踪控制器监测核心与缓存之间的读请求。读缺失时分配记录，缓冲区剩余空间低于阈值则让选定核心暂停推进指令。另一独权从缓存到内存一侧观察请求，并在缓冲区不足时使缓存停止发出新的内存请求。

  1. 启用调试模式

    追踪电路仅在指定模式下监测选定的访存路径。

  2. 识别缺失读

    根据缓存响应选择需要记录的请求。

  3. 占用追踪条目

    为该请求分配与缓存阵列不同的缓冲位置并记录事务。

  4. 缓冲区不足时施加回压

    按观察点停顿核心或缓存发出端，等待追踪记录释放空间。

权项与实施例约束

权利要求 3、4 让选中的请求先暂存，记录写入追踪缓冲区后才删除暂存记录。依权利要求 6，追踪记录可由缓存回填数据生成，因而需要把回填与原始请求正确对应。

图解与对照

  • 追踪记录由访存路径旁路采集
  • 多次缺失使追踪缓冲区逼近阈值
  • 观测点决定停顿对象
  • 区分被测延迟与追踪开销

工程推演与验证

收益与开销

调试器可以由同一请求关联缺失与回填，代价是未完成请求可能长期占据暂存条目。对同一请求 ID 记录暂存分配、回填抵达、追踪提交和暂存删除，有助于分辨条目被哪个阶段占用。

边界场景

让两个核心同时产生缺失，保持外部内存延迟，分别改变回填的交错顺序。若被选请求的记录错绑到另一笔回填，记录完整率再高也无法据此重建正确的执行路径。

条件推演

初始条件
调试模式下连续发生缓存读缺失，追踪缓冲区可用条目降到阈值以下。
处理结果
权项 1 中追踪控制器向选定核心发出停顿信号，解除后这些核心才恢复处理指令。
结果解读
记录比较应标出追踪引入的停顿周期。调试数据包含额外回压，不能直接作为正常运行的访问延迟。

  • 标签流水线发出前预留重试槽

    US12430224B2 的权利要求 15 在追踪缓冲区不足时用回填缓冲暂存相关信息，并反压缓存的新内存请求。US20250103520A1 在允许请求进入标签流水线之前预留重试槽，以保证随后需要再次处理的请求能留在控制器中。用这两种设计分析流水线停顿时，应分别记录调试追踪空间和事务重试空间。
