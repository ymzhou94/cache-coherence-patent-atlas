跨寄存器文件的转换和复制可以留在 LSU 执行

Operation fusion for instructions bridging execution unit types

当浮点执行单元不能直接读整数寄存器文件时，怎样避免先搬运整数、再等待浮点转换的串行执行？

  • 核心结论

  • 移走 dummy load 后目标域无需等候中间值

  • 整数转浮点与标量广播使用不同数据运算

核心结论

LSU 在原有访存执行电路旁增加寄存器传输执行电路。它沿可访问整数寄存器的入口读取源操作数，在同一路径转换或复制，再写入另一类寄存器文件。融合执行省去目标域对搬运中间结果的依赖。

LSU 已有跨寄存器文件的读写连线

原图 2 将跨寄存器文件运算放入乱序 CPU 流水线和 LSU。原图 8 的 CPU complex 运行 OS 与应用，说明书称其处理器为 application processors。原图 10 给出电池供电手机用途。

原图 1、2 中整数电路和浮点／向量电路各有寄存器文件。LSU 能读整数寄存器并把结果送入浮点／向量侧，因此最小的结构变化是在 LSU 内部增加一条通路，复用跨域连线。发射端口区分真实访存和跨域寄存器运算。真实 load/store 继续进入包括 AGU、TLB 和 load/store queue 的访存电路。

移走 dummy load 后目标域无需等候中间值

原图 3A 先把整数读出，以 dummy load 借访存流水线送往浮点侧，再由浮点执行单元执行转换。空跑的流水级延迟即便没有真正的地址翻译和缓存请求仍能存在。原图 3B 中 LSU 传输执行电路直接取整数并转换，最终值送回目标文件。实施例中可能同时少用一项 op、一项派发和发射带宽、一个 ROB 条目及一个中间物理寄存器。

说明书给出 dummy load 在示例访存管线传递至少三拍的情况。收益应计量从源就绪到依赖消费者可取得最终结果的变化，具体周期需要同样的分派及旁路条件。

融合既可直接译出，也可在 MDR 等待资源判断

原图 3B 的取指译码先检测源和目标的寄存器类别，并检查所需操作是否受支持。一种实现先译成可独立执行的两项操作，同时附可融合标识；MDR 再看可用通路后合为一项。说明书也允许取指译码阶段直接产生单项操作。

整数转浮点与标量广播使用不同数据运算

原图 4A 的整数转浮点生成目标浮点表示。原图 4B 的复制把一个标量值写到向量中的一个或多个元素。可复制浮点／向量单元已有的对应功能电路到 LSU；具体处理器是否保留两处电路、时钟及电源门控如何实现由设计决定。

CPU 内的执行资源从浮点／向量的一般执行管线转移到 LSU 的保留站、寄存器传输电路及结果网络。混合负载若在同一保留站积压，跨域指令与真正访存操作仍可能发生排队竞争。
