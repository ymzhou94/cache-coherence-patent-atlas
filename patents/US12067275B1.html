I/O 代理在同一请求存储体中划分顺序子域

Memory bank with subdomains

多个外设共用 I/O 代理的请求存储体时，一个外设的未完成事务会阻塞另一个外设吗？

工程要点

I/O 代理把不同外设的事务分到同一个请求存储体中的独立顺序子域，对外仍由一致性管理电路作为一个代理处理。

成立条件
子域隔离内部顺序依赖，存储容量和外部一致性资源仍共享。
验证方法
在相同外设负载中阻塞 A 的队首，比较 A、B 分属同一子域和不同子域。记录两个子域的队首、B 请求发出周期和共享存储占用。

工作机制

多个逻辑流共享一个请求存储体可以节省物理资源。如果所有请求合到同一顺序链上，外设 A 的阻塞可能拖延外设 B。

I/O 代理把不同外设分配到子域。同一个请求表（TOR）存储体承载多个子域，并按各自链表组织事务。外部一致性管理电路可以仍把它看成单一缓存代理。

  1. 为外设分配子域

    选择能够区分不同请求流的逻辑标识。

  2. 将事务写入共享请求表

    请求条目保留其子域关联，可以使用同一物理存储体。

  3. 在各子域内维护顺序

    根据对应顺序链判断哪一笔事务具备发出条件。

  4. 向一致性管理电路暴露一个代理

    不同子域共享同一 I/O 代理身份，目录无需把每个子域建成独立代理。

图解与对照

  • I/O 请求表物理共享、顺序链按子域划分
  • A 等待时 B 可发出
  • 三种约束由不同结构负责
  • 怎样定位仍存在的等待

实验与取舍

何时有效
域间隔离可减少不同外设因共享顺序链导致的队首阻塞。
代价和限制
共享容量和发出端口仍可能饱和。域数量与外设带宽分布不匹配时，管理成本可能增加。
验证指标
按子域测 TOR 占用、事务入队至发出的等待、域内依赖等待与端口饱和时间。

教学算例

初始条件
外设 A 的一个请求在等待响应。外设 B 也已在同一 TOR 存储体登记可执行请求。
处理结果
由于 A、B 关联不同子域，A 的顺序依赖不会阻塞 B。
结果解读
这项独立性针对域间顺序，不保证物理端口、互连信用或内存带宽无限。

权利要求与出处

独立权利要求为第 1、14、18、23 项。下方列出部分权利要求的中文释义。

权 1
按设备分配子域，事务同存于一个存储体，各子域不因其他子域的事务而阻塞。
权 14
方法权项按外设带宽设置子域数量，并把两个设备的事务关联不同子域。
权 18
SoC 权项将多个独立网络、I/O 簇、虚拟通道和子域纳入同一系统。
权 23
外部的内存管理电路把该存储体作为一个缓存代理维护一致性。
