GPU 按共享缓存亲和性分派工作并在空出时重分配

Affinity-based graphics scheduling

一组 GPU 子单元已发完分配给它的工作，能否协助另一组而维持既有缓存亲和性策略？

工程要点

GPU 硬件先沿软件设定的缓存亲和性映射分派。另一组分派完原有份额时，工作共享电路更新状态机，将一部分剩余工作转给该组。

成立条件
重新分配以另一组已分派完各自份额为触发。该组已分派的工作此时仍可能在执行。
验证方法
固定初始亲和性映射及工作组用时，比较分派尾段禁止和允许跨组共享。记录重分配量、各组缓存缺失、下层字节数及内核最后一项完成的时点。

工作机制

每组 GPU 子单元具有各自共享的缓存。软件提供图形工作的初始亲和性映射，硬件负责按映射分派。

当另一组已分派完其份额，工作共享控制电路更新有限状态机。控制器可以覆盖软件的初始映射，将原本属于第一组的部分工作重新分派。

  1. 提供亲和性映射

    软件提交图形工作或计算内核，并标出在哪一个 GPU 子单元组执行。

  2. 按组划分工作

    分发电路按映射把不同份额送往相应组。各组分别共享自己的缓存。

  3. 检测另一组的分派进度

    控制电路检查另一组已分派完其原份额的条件，并推动硬件有限状态机。

  4. 转移部分剩余份额

    状态机进入相应状态后，硬件重新映射部分尚待分配工作。已经执行的操作不需要重新执行。

工程推演与验证

收益与开销

收益由减少最后一组空转和缩短负载尾段构成。代价是改变工作所在的缓存组，可能增加缓存缺失、下层传输字节数与各组请求队列等待。

边界场景

保持各组算力与初始工作量差异不变，增大 A、B 使用的数据重叠度。若分派尾段缩短但 kernel 完成反而推迟，可比较新增缓存缺失和下层带宽利用率。

条件推演

初始条件
组 A 还有待分派工作，组 B 已发完自己的份额。
处理结果
达到共享条件后，可把 A 的部分工作重新分配给 B。权 1 的条件是已经分派完成，不能直接当作所有指令均已执行完成。
结果解读
比较两组的利用率、共享缓存缺失和内存流量。GPU 工作组亲和性与 CPU 线程亲和性采用不同调度实体。

关联专利

  • 按核簇共享资源饱和度迁移单个线程

    US12333339B2 的 GPU 分派硬件从软件给出的初始工作映射开始，在某组已发完原份额后按硬件状态重新分派。US12147839B2 由性能控制逻辑识别核簇共享资源压力，再由 OS 调度器决定具体线程是否迁移。两边的调度对象分别是 GPU 工作组和 CPU 线程，观测点分别在硬件分派器和核簇资源。

  • 按执行依赖提高 CPU、GPU 和神经处理器的重叠

    US11775811B2 按运算的依赖图从就绪节点中选择可提高处理器并行活动的工作。US12333339B2 在 GPU 内按照软件映射分派工作组，并允许硬件在某组发完原份额后重新分派。前者决定何时向哪个执行资源提交一项就绪工作，后者决定 GPU 内部由哪组资源接收工作组。

  • GPU 逻辑槽映射给高优先级图形工作预留硬件槽

    US12175300B2 用软件优先级约束逻辑槽到硬件槽的映射，低优先级工作只能使用未预留槽。US12333339B2 在先有的软件映射上允许 GPU 硬件按分派进度重新分配工作组。对照时注意预留槽影响工作能否映射，重分派影响获准进入的工作交给哪组执行资源。
