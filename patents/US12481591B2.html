way 预测验证后，何时可以省去重复 tag 比较

Prediction confirmation for cache subsystem

反复访问仍驻留在同一 way 的缓存行时，如何省下重复的 tag 读取和比较，又在逐出或地址转换失效后恢复检查？

  • 验证一次，缓存控制器记住对应行和 way

核心结论

首次用请求 tag 与候选 way 的缓存 tag 核对，预测正确后置确认位。后续再次访问同一行且确认状态仍有效，可直接取数据。缓存行逐出或相应地址转换失效时，控制器复位确认位。

验证一次，缓存控制器记住对应行和 way

归档 0014–0015、0033–0035 分别给出 CPU 取指和数据缓存路径。归档 0046–0049 与原图 7 把同一缓存子系统置于可用于手机的 SoC，权项覆盖该硬件中的 way 预测验证。

原图 2 的请求者是取指单元，原图 3 的请求者可以是 CPU 核。图 1 画数据缓存中的路径。预测电路给出 way，确认位为 0 时由比较电路核对请求 tag 和候选 way 的缓存 tag。两者相符后，控制器可给请求者返回缓存行。

图 2 把原图 4 的确认位矩阵和缓存位置对应起来。确认位按组索引和 way 寻址。一个坐标的置位只对应当前被验证的缓存行。后续复用仍以请求对应同一行为前提。

重复访问省去比较，失配仍需搜索其余 ways

图 3 追踪同一有效行的两次访问。首次核对结果用于第二次访问。再次命中确认状态时，缓存控制器可抑制候选缓存 tag 读取和比较。权利要求 12、19 另写出两侧标签存储器的读省略条件。

候选 tag 不一致时，说明书让缓存控制器转入其他 ways 的搜索。找不到时可向下一级请求。绕开重复验证的收益取决于同一行在一个驻留周期内的重复访问次数。

逐出和地址转换无效都会结束确认状态

图 4 跟踪从已确认到未确认的状态变化。权利要求 7、15 规定逐出时清位，权利要求 8、16 给出该行对应地址转换无效时的清位。缓存行失效，以及带缓存刷新的上下文切换，也出现在说明书的实施例中。

可在相同访存序列下比较预选 way 的 tag 阵列读次数、比较次数和请求到数据返回的时间。需要另算确认位存储访问和复位开销。说明书没有给出具体功耗或延迟数值。
